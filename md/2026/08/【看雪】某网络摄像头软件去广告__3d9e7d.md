> 
> - **定位方式：** 未混淆代码可直接搜索广告关键字找到开屏广告启动入口，回溯调用链确定从 AndroidManifest 的 LauncherActivity 发起。
> - **广告开关：** 广告控制逻辑含 `AdControl.sFreeAd`（新用户免广告）和开发者后门开关；修改 smali 中 `const/4 p0, 0x1`，令 `sThirdAdType = 0` 强制进入无广告分支。
> - **签名校验绕过：** 每次 Activity `onCreate` 调用 `appVerification`，受编译期常量控制；将 `sput-boolean v0` 改为 `v1` 可关闭签名校验，并顺手把 `sIsCheckRoot` 也改为 false。
> - **闪退处理：** 重打包签名后闪退，logcat 报 `entry classes6.dex is tamper`，定位到 `com.security.shell.V5App`（顶象加固）；由于 dex 本身未加密，直接修改 AndroidManifest 的 application 及 appComponentFactory，替换加固入口为正常入口后启动成功。
> - **最终结果：** 重打包签名安装后应用正常启动，广告全部关闭；全程在 Java 层完成，无混淆代码降低了难度。

## 背景

目标应用: 一款网络摄像头工具，家里人经常用来查看摄像头，但是软件中塞了一大堆牛皮癣广告  
广告行为: 开屏广告，热点区域广告，摇一摇跳转，关闭按钮不方便点击且容易误触广告，各种坑老陷阱

### 重打包

接下来重新打包软件并签名，所以要先处理一下签名校验问题，通过反编译的代码可以看到这里有个检验的逻辑  

![图片描述](https://cdn.jsdelivr.net/gh/zhiyu-zeng/img@main/img/2026/08/a501632c8e448394.webp)
  
在每次 activity 的 onCreate 中触发 appVerification 方法，这里也是有开关控制的，而且是编译期常量  

![图片描述](https://cdn.jsdelivr.net/gh/zhiyu-zeng/img@main/img/2026/08/85f654fba4cd595d.webp)
  
所以这里还是继续改 smali  

![图片描述](https://cdn.jsdelivr.net/gh/zhiyu-zeng/img@main/img/2026/08/2933c238d0ddad80.webp)
  
这里把 `sput-boolean v0, Lcom/macrovideo/sdk/GlobalConfiguration;->sIsSignatureVerification:Z` 的 v0 寄存器改为 v1 即可  

![图片描述](https://cdn.jsdelivr.net/gh/zhiyu-zeng/img@main/img/2026/08/24daed00dba2d954.webp)
  
把 sIsCheckRoot 也一起改为 false 了

## 总结一下

总体来说整个过程还是比较顺利的，先定位广告来源，分析展示逻辑并 nop 掉，过签名校验，替换加固代码入口，重打包。因为整个操作都是在 Java 层，而且应用本身就有关闭广告的逻辑，所以基本上是没有什么难度的，最终也是成功实现了去广告的效果。(没有经过混淆的代码看起来真的是太舒服了)
