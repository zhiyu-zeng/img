## 文件头是什么？

每个文件的开头几个字节，是这套格式的"身份证"，行话叫魔数（Magic Number）。

PNG 永远以 89 50 4E 47 0D 0A 1A 0A 开头；JPEG 永远是 FF D8 FF；ZIP 是 50 4B 03 04；gzip 是 1F 8B

不管后缀改成什么、文件名起得多清纯，前几个字节都骗不了人，所以解题第一步，那就是别信后缀，直接看头部（file 命令干的就是这件事）

binwalk 更狠一点，它不止看头部，还会把整个文件从头扫到尾，把所有魔数出现的位置全列出来（这里提一嘴，出题人有个惯用爱好：那就是把一个 ZIP 拼在 PNG 屁股后面）

![图片](https://cdn.jsdelivr.net/gh/zhiyu-zeng/img@main/img/2026/11/2c1bec80a1b17f27.jpg)

这张小抄收好（高频魔数），后面都可以用：

```
89 50 4E 47 0D 0A 1A 0A   PNG 图片
FF D8 FF                    JPEG 图片
47 49 46 38 (GIF8)          GIF 图片
50 4B 03 04 (PK..)          ZIP 压缩包
52 61 72 21 (Rar!)          RAR 压缩包
1F 8B                       gzip 流
42 5A 68 (BZh)              bzip2 流
25 50 44 46 (%PDF)          PDF 文档
53 51 4C 69 (SQLite)        SQLite 数据库
7F 45 4C 46 (.ELF)          Linux 可执行文件
```

OK，热身结束，上题。

## 题目A：后缀是jpg，真身是PNG

第一题最简单也最经典：一个叫"伪装照片.jpg"的文件，图片查看器打不开。

扔进扫描器，输出如下：

![图片](https://cdn.jsdelivr.net/gh/zhiyu-zeng/img@main/img/2026/11/355888e31319888f.jpg)

两行就破案。后缀写着.jpg，但前 8 字节是 89 50 4E 47——ASCII 里 50 4E 47 就是 P、N、G 仨字母，头部识别直接给结论：PNG image。

把后缀改成.png，图立刻就能打开了。这种题在赛场上就是送你一个热身分，考的就一件事：知不知道后缀不可信。

## 题目B：没有后缀的49字节乱码

第二题更进一步：一个叫 no_extension 的文件，什么后缀都没有，记事本打开全是乱码。

![图片](https://cdn.jsdelivr.net/gh/zhiyu-zeng/img@main/img/2026/11/f849f379559e382a.jpg)

扫描器输出：

前两个字节 1F 8B，命中 gzip 流。解压看看里面是什么：

flag{H34d_T3ll5_Th3_Truth}——flag 本身就是宣言：头部讲述真相。出题人在这儿埋了个小幽默，我解出来的时候笑了一下，你呢？

"无后缀 + 压缩流"这个组合在实战里出现频率很高，思路就两步：看头、解压。gzip 里面还可能再套一层 base64，那就是编码篇的内容了，先埋个钩子，后天讲。

## 题目C：一张图里藏着另一个文件

第三题上强度："拼好的图.png"，双击打开是张正常图片，肉眼看不出任何问题。

但扫描器扫出来的东西就多了：

![图片](https://cdn.jsdelivr.net/gh/zhiyu-zeng/img@main/img/2026/11/41344a4204298c92.jpg)

重点看这几行：文件里出现了 3 个魔数痕迹——PNG 在 offset 0（正常），但 offset 1371 的地方冒出来一个 ZIP archive，offset 1487 还有一个 ZIP 尾部标记。

这就是拼接：PNG 数据结束之后，后面又缝了一个完整的 ZIP 进去。图片为什么还能正常显示？因为解析器读到 PNG 的结束块就收工了，后面的字节它根本不看。出题人利用的就是这个来形成“灯下黑”

按扫描结果动刀：从 offset 1371 开始切到底，存成 extracted.zip，解开：

flag{M4gic_Sc4nn3r_D1} 出炉。

整个利用链捋直了：全文件魔数扫描 → 定位隐藏 ZIP 头 → 切割提取 → 解压拿 flag。这就是 binwalk 一条命令（binwalk -e）背后干的事。今天我们手工走了一遍——以后再按 binwalk 回车的时候，你心里是有画面的。

## 这招在工作里也用得上

别以为这只在 CTF 里值钱。

政企安全检查里，"改后缀"是最常见的绕过姿势：把 exe 改成.jpg 骗过邮件网关，把压缩包改个后缀混过附件审查。防守侧的邮件安全设备，核心能力之一就是不看后缀看魔数——跟今天这套逻辑一模一样。

出题人用魔数藏东西，防守方用魔数拆伪装。同一个原理，攻防两个方向——你在 CTF 里练的每一次"识破"，都是给真实工作练手感。

## 手写扫描器，核心就几十行

把今天的主角放出来。魔数表 + 两个函数，一目了然：

```python
MAGIC = [
    (b'\x89PNG\r\n\x1a\n', 'PNG image'),
    (b'\xff\xd8\xff',      'JPEG image'),
    (b'PK\x03\x04',        'ZIP archive'),
    (b'\x1f\x8b',          'gzip stream'),
    # ... 按需扩展
]

def head_type(data):          # file 的逻辑
    for sig, name in MAGIC:
        if data.startswith(sig):
            return name

def scan_all(data):           # binwalk 的逻辑
    hits = []
    for sig, name in MAGIC:
        start = 0
        while True:
            i = data.find(sig, start)
            if i < 0: break
            hits.append((i, name))
            start = i + 1
    return sorted(hits)
```

head_type 看开头，scan_all 扫全文。如果要带去比赛，再往 MAGIC 表里补全几十个常见魔数，然后给 offset 附近加一段 hexdump 预览，就算是一个能进考场的自用工具了～

有个提醒要说下：就算扫出多个魔数也不一定都是拼接！JPEG 内部就天然含有长得像压缩流的字节序列，会有误报。位置对不对，要结合文件大小和结构合理性自己判断

工具只报坐标，判断还在于人！So要记住：工具给你的是线索，最后破题还得靠你自己的脑子。
