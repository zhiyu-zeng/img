**信息网络安全杂志** *2026年11月9日 12:00*

论文发表于网络安全领域顶级会议 IEEE S&P 2026 ，并获得Artifact 评估中的 Available、Functional 和 Reproduced 三项徽章。在跨浏览器与跨硬件的隐蔽信道研究中，文章发现了一种基于GPU命令队列竞争的新型隐秘信道，针对该信道实现了开源的稳定通信框架C3F。通过在真实环境下进行的大规模测评，该研究证实了其工程可行性，并促使全球主要浏览器厂商确认漏洞并着手修复，体现了该工作在系统底层安全研究与实际防御中的应用价值。

【引子】

在现代 Web 安全中，浏览器沙箱和进程隔离（如 Chrome 与 Safari 的隔离，或正常与无痕模式的隔离）一直被视为保护用户隐私的最后底线。当现有研究受限于单浏览器内部资源共享、且极易被真实环境噪声干扰时，在网络安全顶会S&P 2026发表的这篇Practical Covert Channel across Isolated Browser Instances via GPU Command Queue Contention提出了一种的新范式：绕开纯软件层面的隔离，利用底层全局共享的 GPU 命令队列制造竞争，建立高可靠的跨域隐蔽信道。

【论文速览】

研究背景：

此前挖掘浏览器隐蔽信道的主流方案面临两大瓶颈：

一是跨界能力受限：现有方案（如 Pool - Party 等）高度依赖单浏览器内部的资源池，只能在同一浏览器的不同模式间通信。这导致它们根本无法穿透用户为了隔离风险而使用的不同浏览器（如分别用 Chrome 和 Safari 处理个人与工作事务），攻击面大打折扣。

二是真实环境下的极度脆弱与低效：为了制造信道（如 SideR），必须利用 100% 的 GPU/CPU 渲染资源。这不仅会在真实多任务场景中引发严重的系统卡顿，直接暴露攻击行为，而且传输效率极低（传输 512 bit 的 Cookie 数据竟需要半小时）。这意味着，在用户正常的网页平均停留时间（约 52 秒）内，攻击者根本来不及窃取任何有价值的数据，攻击在真实场景下必然失败。

核心思路：

发现并利用了 OpenGL 同步机制（OpenGL synchronization）中的硬件调度特性，提出了一种基于 GPU 命令队列竞争的底层侧信道，并设计了四层架构的动态通信框架 C3F。其核心机制是：发送方通过执行复杂度可控的绘图指令来人为制造 GPU 队列拥堵；接收方则高频发射轻量级探针（Probes），通过测量同步指令的“排队延迟”（Delay）来精准解码二进制数据。

关键结果：

通过在 Amazon Mechanical Turk (AMT) 平台上对 1434 个被试者提供的多样化真实计算机设备（涵盖 Intel, NVIDIA, AMD, Apple 等各型号 GPU）进行大规模实测，C3F实现了 92.81% 的高通信完成率，且一旦完成握手与传输，数据准确率高达 100%。该框架不仅无视进程隔离，在Chrome, Edge, Firefox, Safari 等所有主流浏览器上均实用，其揭露的底层硬件安全威胁更是直接促使 Firefox, Safari 和 Tor 官方确认漏洞并着手开发修复补丁。

【深度解剖】

论文对“浏览器微架构隐蔽信道”提供了重要的范式突破。通过与该领域近几年的三篇顶级工作对比，可清晰锚定C 3 F 的学术坐标：

1.突破同源/同浏览器的物理隔离界限：USENIX 2023 的 Pool - Party 确立了利用资源池构建信道的方法，但受限于浏览器内部隔离机制，无法实现跨浏览器通信。C 3 F 敏锐捕捉到了 GPU 是全局共享的底层硬件这一盲区，成功穿透了操作系统级别的进程隔离，实现了 Chrome 与 Safari 之间的跨端跨界通信。

2.规避高资源占用与极端环境依赖：USENIX 2022 的 SideR 虽然实现了渲染竞争信道，但要求 100% 拉满 GPU 资源，在真实多任务场景下极易断连且带宽极低（0.3 bps）。 C 3 F 摒弃了对硬件资源的绝对占用，转而利用 GPU 命令队列微观层面的“排队延迟”，实现了灵活且隐蔽的传输，带宽提升近 30 倍，实现在用户察觉前完成 Cookie 同步。

3.克服真实世界设备的异构性噪声：USENIX 2017 的 Loophole 依赖固定的时间阈值，在面对真实用户设备复杂的网络与渲染噪声时常常失效C 3 F 极具创新性地引入了类似计算机网络的四层协议架构（会话、传输、编码、原始信道）。在 Setup 阶段进行动态握手（Handshake），自动适应不同显卡（如 Apple M1 vs RTX 4060）的性能基准，并配合 CRC - 32 校验与重传机制，实现了真实环境下 100% 的抗噪准确率。

4.四个层级的主要工作：

会话层（Session Layer）通过动态握手机制，自动测试并协商出适合当前系统性能的渲染时间基准。

传输层（Transmission Layer）负责数据帧的封装与 CRC-32 完整性校验，并结合自动重传机制确保极高的传输准确率。

编码层（Encoding Layer）利用聚类算法（Clustering Algorithm），将底层参差不齐的硬件延迟问题精准还原为二进制比特流。

最底层的原始信道层（Raw Channel Layer）则直接与 GPU 指令队列交涉，由发送方执行复杂运算刻意制造队列拥堵，接收方高频发射轻量级探针以精确捕获排队延迟。

底层工程实现层面：

C 3 F 深入 WebGL 渲染管线的核心，巧妙组合了异步绘图指令（drawArrays）与隐式同步指令（readPixels）。当发送方塞入一个执行复杂 sin(x) 循环计算的载荷时，接收方的轻量级探针指令在 GPU 队列中被迫等待，从而在 JavaScript 的 performance.now() 计时器中产生几十毫秒级的精确延迟问题。配合其独创的聚类算法，将这些微小的硬件排队时差完美还原为清晰的二进制比特流。

【局限与展望】

尽管C 3 F 通过精巧的重传与握手协议解决了噪声问题，但其通信效率仍受限于底层防御机制：当遇到极度随机的时间模糊防御（Fuzzy - time defense，如 Tor 浏览器强制加入的计时器随机抖动）时，系统为了保证 100% 的准确率，会频繁触发重传，导致传输带宽受到明显压制。未来该方向的安全探索值得关注以下两点：

1.从“主动通信”到“被动窃听”的演进：目前的命令队列竞争主要用于构建恶意标签页间的隐蔽信道。未来完全可以将其升维为侧信道攻击（Side Channel），例如通过监控 GPU 队列延迟问题，逆向推测其他无辜标签页正在进行的 AI 推理任务、密码学运算或渲染的敏感网页内容。

2.GPU 资源的硬件级动态隔离：此研究证明了纯软件的浏览器进程沙箱在面对共享硬件时已大范围失效。未来的防御体系迫切需要操作系统层面和显卡驱动厂商（如 NVIDIA, Apple）联手，在硬件调度层实现针对不同进程的 GPU 时间与空间细粒度硬隔离。

在 Setup 阶段进行动态握手（Handshake），自动适应不同显卡（如 Apple M1 vs RTX 4060）的性能基准，并配合 CRC - 32 校验与重传机制，实现了真实环境下 100% 的抗噪准确率。
