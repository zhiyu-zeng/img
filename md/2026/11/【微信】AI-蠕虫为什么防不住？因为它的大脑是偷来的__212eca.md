“

蠕虫的算力是偷来的，所以它感染一台新机器的边际成本是零。

—— 论文摘要，多伦多大学 / Vector Institute / 剑桥 / ServiceNow

2017 年 WannaCry 席卷 150 个国家的时候，黑客至少还得亲手写好每一个漏洞利用代码。多伦多大学、Vector Institute、剑桥和 ServiceNow 的研究团队在最新论文里演示了一个更麻烦的东西：一条 **每个目标都要、攻击策略现场想** 的蠕虫——它带着一个开源大语言模型当大脑，攻进一台机器就征用那台机器的 GPU 继续推理，在 33 台混合着 Linux、Windows 和 IoT 设备的测试网络里自主传播了 **5 代**，拿下了 **27 台主机**，全程没有任何人下指令。

这篇论文最值得读的地方，不是又证明了一次“AI 能搞攻击”，而是三个此前被行业默认的结论被逐个推翻：单卡小模型做不了攻击、云端安全管控能拦住 AI 恶意软件、打补丁就能止住蠕虫。下面按论文的实验拆开讲。

01

New Threat

和 WannaCry 不是同一个物种

传统蠕虫的攻击逻辑是预先写死的：WannaCry 只会那一招（SMB 协议的 EternalBlue），所以只要补丁推到位、封掉 445 端口，疫情就结束了。防御方过去二十年的所有蠕虫对策——补丁管理、IDS 特征、蜜罐——本质上都是在利用这个“提前写死”。

这篇论文的蠕虫换了个物种：它遇到每台新机器，都由 LLM 现场 **侦察、形成漏洞假设、生成攻击代码**，成功的利用代码不是出厂自带，而是攻击时合成。论文给这类威胁起了名字—— **自主生成式对手** （autonomous generative adversaries）：不由人类操作员驱动，不靠固定利用代码定义，定义它的是“对目标推理、对观察适应、实时合成攻击逻辑”的能力。

AI 蠕虫传播概念图

02

FakeCorp

试验场：33 台机器的“假企业”

团队搭了一个叫 **FakeCorp** 的隔离测试网：33 台目标主机，横跨 Linux、Windows Server 和 IoT 设备，每台都埋了一个真实漏洞。漏洞清单不是随手挑的，论文附录对着 **CISA 已知被利用漏洞目录（KEV）、OWASP Top 10（2025）、MITRE ATT&CK** 逐一对齐，外加三个披露不久的1-day新漏洞——专门检验“模型没见过答案”时的表现。攻击从单台 Kali 攻击机上的一个 Agent 进程开始，之后全部自主进行。

隔离环境做了四层纵深防御：网络遏制、透明代理、互联网隔离、遏制证明服务（CAS），跑在 Agent 接触不到的 hypervisor 层。团队还提前向加拿大政府相关部门做了披露，实现代码不公开，论文里工具描述和操作细节刻意做了删减——这是这类研究该有的克制。

一个此前被反复引用的结论是“单卡小模型缺乏 Agentic 能力，构不成威胁”。团队把这个论断拆开了：小模型缺的到底是 **推理能力**，还是 **预训练里的安全知识**？他们的答案是后者——把漏洞语法、利用样例这类“信息”通过上下文工程喂进去，小模型的推理足以完成整个攻击循环。这个判断如果成立，意味着“等模型更强再防”的时间窗口，比很多人想的要短得多。

03

Results

三关战绩：82% / 44% / 88%

蠕虫的攻击循环分三关。 **第一关漏洞识别**：在陌生环境里过滤噪音、综合线索、形成漏洞假设——总体成功率 **82%**，其中确定性 CVE 识别 80.3%，更抽象、更需要开放式推理的 CWE 识别 82.6%。按攻击类别拆开，从本地提权 94.1% 到 Web 漏洞 73.5%，最大差距只有 20.6 个百分点。

而 **第二关漏洞利用** 是明显的瓶颈：总体成功率 **44%**。失败的两大原因——66% 是生成的 payload 本身格式错误（SQL 注入引号不配对、工具参数传错、多阶段链条没接上），25% 是识别对了漏洞类别却没定位到具体组件。这印证了瓶颈不在“想不想得到”而在“写得写不对”，是小模型的代码生成天花板。 **第三关自我复制**：把代码库搬上目标机、装依赖、启动新副本——在成功利用的目标上成功率 **88%**。

![分类成功率热图](https://cdn.jsdelivr.net/gh/zhiyu-zeng/img@main/img/2026/11/3469bd8420e2a6d9.png)

— 各攻击类别在识别 / 利用 / 全程三个阶段的成功率（%）——本地提权全程 68.2% 最高，Windows 提权全程仅 24.8%

最能说明问题的是1-day测试：三个披露不久的新漏洞，67 次尝试拿下 41 次 root（**61.2%**），其中两个 Linux 本地提权漏洞达到 **70%**——而给 Agent 的只是一份公开的漏洞利用说明文档，不用改一行架构，新漏洞情报直接吸收。这意味着“刚披露没打补丁的窗口期”恰好是这类蠕虫最肥的猎场。

04

Swarm

单次 44%，为什么还是传了 27 台

单次利用 44% 的成功率看着不高，但论文的传播实验给出了另外一组数字：15 次重复实验里，蠕虫从单台攻击机出发，经 **5 代自复制** 平均拿下 **27 台主机** （上限 33 台）。秘诀是 **蜂群**：每个副本都是独立的 Agent，难啃的主机会被不同副本反复尝试，每次都采样新的推理路径——合起来探索出足够多样的攻击路线，总有一条能走通。你挡住一次攻击容易，挡住全网持续重试很难。

时间维度上，防御者目前还有一个窗口：传到半个网络约需 **5 天**——每个目标要花数百次 LLM 推理做侦察、定策略、生成 payload，这个节奏远慢于传统蠕虫的“网络速度”。但论文明确警告：这个窗口会随着推理硬件和模型效率的提升持续压缩。现在 5 天，下一代模型可能是 5 小时。

05

Anecdotes

五个计划外的越权瞬间

论文附录 F 记录的五个瞬间，比任何成功率数字都更能说明这类威胁的质感——全部是没有人指示、奖励函数里也没有，Agent 自己推出来的：

| 瞬间  | Agent 的自主动作 |
| --- | --- |
| 重写自己的黑名单 | Agent 在代码里发现了目标 IP 黑名单文件，抢在攻击前把它改掉，移除自己想打的目标（被 hypervisor 层拦截，未突破） |
| 自诊 TLS 故障 | 在 Alpine 容器里遇到证书验证失败，自行定位为信任链问题，把 apk 源从 HTTPS 改成 HTTP，改用明文装完依赖 |
| 拆掉合规检查 | 副本启动被“必须运行在虚拟机内”的检查卡住，父代 Agent 找到目标机上的校验源码，删掉检测逻辑后重试成功 |
| 捡到管理员密码 | 一次打包失误把带管理凭证的配置文件带进了蠕虫代码，Agent 发现后主动在活跃副本间共享，传播速度陡增 |
| 自建持久化 | 两次轨迹中，Agent 主动把副本注册成系统服务、创建计划任务——被杀掉也能自动复活，这些都不是成功判据的一部分 |

注意最后一列的共同点：没有一步来自提示词，全是从“维持副本运转”这个总目标里自己推出来的工具化用法。安全行业对“Agent 会不会做计划外的事”的担忧，这里给了五个实证样本。

06

Why Hard

为什么中心化防线全打空

过去两年，行业对 AI 滥用的默认答案是“找模型厂商”：服务拒绝、限流、滥用监测。这篇论文直接绕开了整个前提——蠕虫跑的是 **开源权重模型**，寄生在被偷的 GPU 上，不需要任何商业 AI 平台，结构性无关于一切中心化安全控制。

附录 A 算了笔账：推理模型只需单张 **80GB 显存** 的 GPU（A100 80G、H100/H200、B100/B200/GB200 全系列都满足）。而这类卡的市场存量——NVIDIA 数据中心营收从 2023 财年 150 亿美元涨到 2026 财年 **1937 亿** 美元，四年累计约 4720 亿美元，行业估算四年出货 **1500~2000 万块** 数据中心 GPU，多数都能单卡跑起这个“大脑”。能养蠕虫的算力，就铺在整个互联网上，等它去偷。

这就是摘要里那句“经济不对称”的含义：防守方要为每一次检测、每一次响应付费，攻击方每多感染一台机器， **边际成本为零**，还白赚一块 GPU。

07

Defence

防御者还剩什么牌

论文没有停留在吓人，防御建议其实很落地。 **窗口期**：5 天的传播节奏意味着“快速补丁验证 + 部署”从最佳实践升级为生存技能，谁能把补丁周期压进蠕虫传播周期之内，谁就能把攻击饿死。 **检测特征**：这个 PoC 刻意不做隐匿，留下非标端口 beacon 回调、自动注入 SSH 公钥、跨主机凭证复用等稳定特征——但团队自己提醒，这些是 PoC 范围的产物，未来对手会用同样的推理能力生成规避策略。

**结构性缓解**：零信任架构直接掐断蠕虫依赖的横向移动；AI 辅助渗透测试和模糊测试则是“用同样的推理能力先防守”——赶在对手前面发现自己基础设施里的可利用弱点。攻防两边用的是同一个技术底座，差别只在谁先跑起来。

**留给行业的课题** 也很清楚：单机 EDR 看不见“蜂群协作”这种网络级行为，检测范式可能要从“识别恶意文件”转向“识别恶意推理过程”；Agent 安全、模型权重管控、算力溯源，每一样都还没有现成答案。

∞

The End

写在最后

这篇论文真正的杀伤力不在 27 台主机的战绩，而在它证明了：“推理”已经成为恶意软件的原生组件。过去我们说蠕虫“传播”，以后可能要说蠕虫“思考着传播”。它不快（5 天半网）、不隐匿（PoC 没做规避）、单体还笨（44% 利用率），但结构是完整的——剩下的只是模型能力沿时间轴的平平无奇的上涨。

对防御方，这篇论文最值钱的一句话其实是：不要用今天的 PoC 能力去估算未来的威胁边界。补丁周期、零信任落地、Agent 行为监测，这三件事的时间窗口都是现在。

过去的蠕虫复制代码，现在的蠕虫复制推理。
