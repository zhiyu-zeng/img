> 所有样本分析必须在物理/网络隔离的虚拟机中进行，关闭共享文件夹、剪贴板、USB 直通，网卡设为仅主机模式或断网，分析前后拍快照。切勿将企业内部敏感样本直接上传到公网 VirusTotal，优先本地库比对。

## 一、分析环境搭建

| 环境类型 | 适用场景 | 推荐工具 |
| --- | --- | --- |
| 轻量沙箱 | 快速筛选、初步研判 | Cuckoo Sandbox、火绒沙箱、Triage、ANY.RUN |
| 定制虚拟机 | 加壳/APT/勒索深度逆向 | VMware + 关闭共享 + 仅主机模式 + 快照 |
| 内存取证 | 密钥残留提取 | DumpIt / FTK Imager + Volatility3 |

**工具清单**：PE-bear / CFF Explorer / DIE / 010 Editor（PE 结构）、Strings / FLOSS（字符串）、IDA Pro / Ghidra（反汇编）、Procmon / Process Hacker（行为监控）、FakeNet-NG（网络模拟）、x64dbg + ScyllaHide（调试）、CyberChef / OpenSSL（密码学）、Wireshark（流量）。

## 二、静态分析

### 1\. 基础画像

-   计算 MD5/SHA256，查 VirusTotal、MalwareBazaar、微步、360 威胁情报中心
    
-   DIE 查壳（UPX、Themida、自定义壳），熵值 > 7.0 通常代表加壳/加密段
    

### 2\. 导入表特征（快速判断能力面）

勒索高频 API 特征速查：

| 能力维度 | 关键 API / 字符串 |
| --- | --- |
| 文件遍历加密 | `FindFirstFileW` 、 `FindNextFileW` 、 `CreateFileW` 、 `ReadFile` 、 `WriteFile` |
| 系统加密 API | `CryptGenRandom` 、 `CryptEncrypt` 、 `BCryptEncrypt` （说明用原生 AES/RSA） |
| 备份销毁 | `vssadmin delete shadows` 、 `wbadmin delete catalog` 、 `CreateServiceA` |
| 持久化 | `RegCreateKeyEx` 、 `RegSetValueEx` 、计划任务、Run 键 |
| 注入/横向 | `CreateRemoteThread` 、 `OpenProcess` |
| 双重勒索/C2 | `WinHttp` 、 `WinINet` 、 `Rclone` 、 `curl` 外联特征 |

> 若导入表 **非常干净**、几乎无 Crypt 系列 API——可能是自定义实现（如 LockBit 手写 Salsa20、Gunra 用 ChaCha20+ChaCha8）。

### 3\. 字符串与配置提取

-   FLOSS 解混淆字符串，重点找：勒索信文本、文件后缀、比特币地址、Tor 域名、互斥体名（如 Gunra 的 `kjsidugiaadf99439` ）、排除目录/扩展名白名单
    
-   硬编码公钥（PEM 头、Base64 大块）、硬编码密钥（如 VEN0m 把 AES-256 key 明文放在 `.rdata` ， `strings` 60 秒即可提取）
    

### 4\. 加密方案预判（2025–2026 主流形态）

现代勒索几乎全是 **混合加密** （Hybrid Cryptography）：

| 层   | 典型算法 | 备注  |
| --- | --- | --- |
| 文件对称加密 | **ChaCha20 / XChaCha20** （取代 AES 成主流）、Salsa20、AES-256-CTR/CBC | 无硬件加速下性能稳，Go/Rust 生态首选 |
| 密钥封装 | RSA-2048/4096、Curve25519 / X25519 (ECDH) | 现代变种偏好 ECDH，缩短密钥交换、减少痕迹 |
| KDF | PBKDF2、Scrypt、BLAKE2b + SHA-512 | 硬编码 salt、低迭代是破解突破口 |
| 密钥销毁 | `SecureZeroMemory` 、删卷影、覆写原文件 | **92.3% 勒索完成加密后主动清内存密钥**——内存转储是唯一高价值窗口 |

家族速查：LockBit 5.0 = ChaCha20-Poly1305 + X25519 + BLAKE2b（大文件分 8MB 块独立加密）；Gunra = ChaCha20/RSA-4096（Win）/ ChaCha8（Linux）， **随机函数弱可预测**；WannaCry = AES-128-CBC；Conti/BlackBasta 系 = ChaCha20 + RSA。

## 三、动态分析

### 1\. 行为监控重点

用 Procmon 抓取并过滤以下关键行为链：

-   **进程创建**
    
    ： `vssadmin delete shadows /all /quiet` 、 `wbadmin delete catalog` 、 `bcdedit /set {default} recoveryenabled no`
    
-   **文件操作**
    
    ：批量 `CreateFile` + `WriteFile` → 原文件被覆写/删除 → 生成 <原名>.<ext> + `README.txt` 勒索信
    
-   **注册表**
    
    ： `HKLM\...\CurrentVersion\Run` 、禁用 UAC、关闭 Defender
    
-   **服务**
    
    ：停止 SQL、Veeam、备份相关服务（LockBit 会杀 60+ 安全/备份服务）
    

### 2\. 网络行为（FakeNet-NG + Wireshark）

-   C2 心跳、Tor 代理、`.onion` 连接
    
-   双重勒索外传：HTTP POST 到 MEGA、云存储、自建服务器（Stealbit、Rclone 特征）
    

### 3\. 反分析对抗观察

LockBit 5.0 等新一代样本常见：

-   进程镂空（Process Hollowing，如挂起 `defrag.exe` 注入 shellcode）
    
-   运行时 API hash 解析、字符串加密
    
-   重载干净 ntdll/kernel32 绕过 EDR hook
    
-   沙箱检测（睡眠、CPU 核数、MAC 前缀、鼠标移动）
    
-   编译期混淆 / 控制流平坦化
    

### 4\. 加密逻辑还原（核心）

-   **断点策略**
    
    ：在 `CryptEncrypt` / `BCryptEncrypt` / ChaCha20 轮函数下断，dump 出 key + nonce + 明文/密文对
    
-   **密钥生命周期追踪**
    
    ：谁生成 → 谁封装 → 存哪里（文件尾部、.keystore、注册表、C2 下发）→ 何时擦除
    
-   对 Gunra，其 Linux 版使用弱 PRNG，nonce 和 key 可预测 → **高概率解密**；对 VEN0m，AES key 硬编码 → 直接提取

## 四、解密可行性评估

| 解密路径 | 适用场景 | 成功率 |
| --- | --- | --- |
| **内存密钥提取** | 感染后未重启、进程仍存活 | 高（黄金窗口） |
| **算法/实现缺陷** | 弱 PRNG、ECB 模式、硬编码 key、RSA 密钥短 | 中   |
| **主密钥泄露** | 执法捣毁团伙服务器（Operation Cronos 等） | 仅特定变种 |
| **No More Ransom 工具** | 已收录家族（数百种免费工具） | 取决于是否命中 |

> 现场处置铁律： **立即断网隔离、严禁重启/关机** （保内存）、用干净 U 盘拷工具、先小范围测试解密再批量。

* * *

## 五、产出：IOC + 检测规则

一份合格分析报告至少包含：

-   文件指纹（MD5/SHA1/SHA256、文件大小、编译时间）
    
-   勒索信样本、加密后缀、互斥体、注册表键
    
-   C2 IP/域名、Tor 地址、比特币地址
    
-   **ATT&CK 映射**
    
    （T1486 数据加密、T1490 删卷影、T1021 横向移动、T1055 进程注入等）
    
-   Sigma / YARA / Suricata 规则、EDR 行为检测查询（像 VEN0m 报告给出 42 条行为检测查询）
    
-   加密结论： **可解密 / 不可解密 / 需等执法泄露密钥**
