**红队安全圈** *2026年11月10日 08:00*

这四条凑得很不好看：没有一条需要 0day 技巧。SSH 只要一个超长密码，GPUStack 只要伪造一个请求头，FreeSWITCH 只要一条 SIP 消息，Aspera 需要的是任意一个合法账号。

## 01 这批是什么

11 月 9 日，一天之内四条漏洞被加进已知被利用清单：OpenSSH、GPUStack、FreeSWITCH、IBM Aspera Faspex。四条都带明确的处置期限，11 月 12 日之前要么打补丁，要么上缓解措施，没有第三条路。

一次进四条，含义很直接：利用已经在发生，不是理论推演。清单上的期限也不是建议，它对应的是已经被打的时间点。反过来看还算好消息，这四条现在都已经有官方补丁或者明确的缓解开关，真等到有人拿它们打自己的系统，再翻配置文件就晚了。

它们对应的资产分别是登录入口、AI 推理集群、电话系统和文件交换节点，四样东西在大多数公司里都不止一台。

## 02 四条各自的要害

CVE-2026-1231588.1 OpenSSH

低于 10.6p2 的 sshd 跑在 musl 上且没编 PAM（Alpine 是典型），只要密码登录还是默认的开启状态、机器上有一个密码字段为 \* 的账号，再加任意一个带 $5$ 或 $6$ 哈希的账号，攻击者发一个 257 到 1024 字节的密码就能登进去，不用重试，一次到位。

10.6p2 已修，升级后必须重启 sshd，只换包不重启等于没修；改不了就关掉密码登录

CVE-2026-1028959.8 GPUStack

2.2.0 之前，GPUStack 把来自 loopback 的请求直接当内置管理员：同机反向代理，或者伪造一个 X-GPUStack-Real-IP: 127.0.0.1 请求头，都能让远程请求冒充本机。进去就是管理员，能改用户和模型、造永久 API key、读 worker 和云厂商密钥，再通过 POST /v2/inference-backends/from-yaml 在 worker 上执行代码。已在野打过 2.1.1，攻击者建的自定义后端在跑反连 shell。

修 2.2.0；临时缓解把 force_auth_localhost 设为 true，并在边界剥掉客户端自带的 X-GPUStack-Real-IP

CVE-2026-1167799.8 FreeSWITCH

入站 SIP MESSAGE 的 To 用户部分按加号切开，左半边被当作 chat proto 名去查表，命中 api 这个接口后直接进 switch_api_execute。谁能给 profile 发一条 MESSAGE，谁就能挑一个 FreeSWITCH API 命令让服务器执行，配置和凭据一起暴露，还能接管全部通话。默认配置里 internal 和 external 都开着 chat，不需要任何非默认设置。

1.11.3 已修（新增 enable-chat-api-proto，默认关闭）；缓解是给不需要聊天功能的 profile 设 enable-chat=false，只上 auth-messages 不够

CVE-2026-1232189.8 Aspera Faspex

IBM Aspera Faspex 5.0.0 到 5.0.19，已认证用户构造一条特定消息绕过授权，直接拿管理员。这条门槛最高，要先有一个能登录的账号，但 Aspera 常放在对外文件交换节点上，一旦被拿就是整条文件通道全开。

按厂商公告升级；升级前先把非必要账号和对外暴露面收一收

## 03 三条自查

三条命令都能在五分钟内跑完，先确认在不在范围内，再决定补丁窗口。

SSH：版本与认证配置

ssh -V

\# 低于 10.6p2 且是 musl 系统就要看

grep -Ei 'PasswordAuth|UsePAM' \\

/etc/ssh/sshd_config

apk info -v openssh-server

GPUStack：伪造头探一下

H='X-GPUStack-Real-IP: 127.0.0.1'

curl -s -o /dev/null \\

\-w '%{http_code}\\n' -H "$H" \\

http://HOST:80/v2/users

\# 返回 200 就是免认证进管理员

FreeSWITCH：看 chat 关没关

freeswitch -version

grep -rE 'enable-chat' \\

/etc/freeswitch/sip_profiles/

\# 没写 enable-chat 的 profile 默认开着

## 04 一句判断

四条里 GPUStack 和 FreeSWITCH 是未认证直接进管理员或命令执行，又常挂在对外开放的端口上，优先级压过 SSH。SSH 那条虽然要满足 musl 无 PAM 的前提，但 Alpine 基镜像满地都是，别拖。

今天先把两个 9.8 处理掉，SSH 按发行版重建 sshd 再重启，能顺手关掉密码登录就一并关掉。

下期继续蹲厂商补丁和 PoC 动静， **关注** 后漏洞先知道，修复不踩坑。
