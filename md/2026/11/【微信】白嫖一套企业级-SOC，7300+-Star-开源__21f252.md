AI 安全运营中心（AI SOC）这个赛道，演示一个比一个漂亮：告警进来，大模型分析，自动响应，全程无人工。但干过安全运营的人都明白，最难的不是让 AI 说话，而是回答“它凭什么这么说”。AiSOC 是一个把这个问题当成产品本身的开源项目：2026 年 5 月开源，半年拿下 **7300+ Star**，44 个 release 迭代到 v22.2.0，MIT 协议，由威胁情报公司 Cyble 出资开发——安装脚本跑完连一个外部 API Key 都不需要。

它是一条完整的安全运营流水线：91 个数据连接器收遥测，2966 条实测可执行的检测规则报警，AI 智能体对每条告警做分诊和调查，每一步推理写进可审计的台账，而任何对外响应动作，必须有人点批准。下面按“它是什么 → 规则怎么管 → AI 怎么用 → 动作怎么控 → 怎么装”的顺序拆开讲。

01

Overview

它是什么：一条完整的告警流水线

AiSOC 的数据通路是一条标准安全平台链路：ingest 接入并归一化（每个事件盖上活动投影：谁、做了什么、对哪个资源、在哪、结果如何），Kafka 做主干，fusion 引擎跑检测规则并叠加租户自己的调优（你在控制台关掉的规则就真的不再触发），相关联的告警聚成事件（incident），然后 AI 智能体进场调查，结论和建议写入调查台账，等人工批准才会触达任何厂商设备。

架构上是 **20 个服务** （14 个 Python、4 个 Go、2 个 TypeScript）撑起 Next.js 控制台。部署分两档：core16 个容器、约 8GB 内存，包含完整告警链路加本地模型和 CISA KEV 威胁情报源；full22 个容器、约 12GB，再加 ClickHouse 事件湖、Neo4j 实体图和 OpenSearch 全文检索。数据接入两种姿势：推送走 ingest API，拉取从 91 个点击式连接器里配——Splunk、Sentinel、Elastic、CrowdStrike、Okta、AWS、K8s 审计都在列。真上云资产不用硬凑 REST：CloudTrail 走 S3+SQS、GCP 走 Pub/Sub、Azure 走 Event Hubs，四类采集器都带可断点续传的游标和背压。

02

Detection

规则库的较真：可执行是证出来的

磁盘上躺着 **7407 条检测规则**，但 README 只敢说其中 **2966 条可执行**——外加 76 条滑动窗口规则（73 条计数、3 条有序序列）。这个数字是硬碰硬测出来的：一条规则要进编译规则集，必须把一个厂商形状的事件回放穿过真实的连接器和引擎，亲眼看着它触发，绝不靠目录扫描或 enabled 标志推断。

更有意思的是拒绝的透明度：编译文档明说 **1362 条规则被拒收** （“拒收”总比“近似转换”好——一条几乎对的规则比缺失的规则更难排查），迁移工具把 Splunk SPL、Sentinel KQL、Elastic EQL 翻译成自家格式，2005 条捆绑的 Splunk 规则里 1734 条可翻译、其中 1711 条是部分翻译，翻译不了就拒绝，而不是给你个差不多对的。还有一条门禁测试会故意回滚 Windows 连接器，要求全部 1687 条 Windows 规则必须随之静默——证明“可达”而不是“碰巧凑数”。目前仍有 2 条规则无法触发（从 119 条降下来），都在等行为基线。

03

AI Triage

AI 分诊：本地小模型 + 全程留痕

AI 部分没有接 GPT：默认网关跑的是 Ollama 本地模型 **llama3.2:3b-instruct-q4_K_M**，约 2GB，CPU 就能推理。项目对它的评价相当冷静：50 条告警上原本只有 44 次给出可用分诊，把回复约束成 JSON 后提到 **50 次**——“它不是前沿模型”，控制台会标注每个判决走的是哪条路径。想换强模型，控制台里配自己的 provider，或用make up-gpu/make up-host-llm换运行方式；但官方从未测过任何托管模型（没有资助的 Key），表格里那些行老老实实写着not measured，而不是 0。

![AI 分诊判决](https://cdn.jsdelivr.net/gh/zhiyu-zeng/img@main/img/2026/11/e85acd56a92348b1.png)

— AI 分诊判决面板：结论、置信度、理由逐字展示，本地模型产出

智能体的边界画得很清楚： **只读** 告警、关联告警、实体上下文和同签名历史判决；只能调用类型化工具（湖查询、图遍历、富化查询），永远不能自己写 SQL；模型填充的是封闭 schema，每个值绑定成参数，连查询语句都表达不出来。每个判决要有据可查：引用了证据里不存在的指标，判决自动降级为人审；发送给模型的 prompt 先过验证，原始日志、OCSF 载荷、长得像密钥的值直接拒收。全部 prompt、工具调用、引用、判决、token 成本写进调查台账，可导出 **签名的证据包**——字节级一致、prompt 存摘要、OCSF 1.9.0 标准。

04

Response

响应动作：三个开关和一个暂停键

响应（SOAR 那部分）是全项目防得最严的地方：playbook 由告警触发后默认只做预览，把计划挂在告警上等确认；真正执行需要部署、租户、playbook **三个开关全部同意**，所有默认值都是关。批准环节是个持久化暂停：运行挂起到 Postgres，重启服务后还能恢复，超时则带着记录过期，而不是永远挂着。

批准的粒度也讲究：批准一个 playbook 不等于授权它将来包含的任何步骤，每个响应步骤在派发时对照自己的能力契约单独评级；审批人必须持有对应权限层级，且 **不能是发起请求的那个人**。没有显式授权，任何厂商设备都不会被碰。

05

Deployment

部署实录：从 clone 到第一条告警

先把门槛说清楚：Docker Compose v2，Docker 虚拟机分 **8GB 内存、20GB 磁盘**，外加 python3（3.9+）和 bash。机器是空的也不怕，Linux/macOS 一行命令装齐所有依赖（Windows 用install.ps1）：

$ curl -fsSL https://raw.githubusercontent.com/beenuar/AiSOC/main/install.sh | bash

$ git clone https://github.com/beenuar/AiSOC && cd AiSOC

$ make up

\# 首次运行会下载约 2GB 的本地模型到专用 volume

\# （只有 make clean 会清掉它）

四个细节值得说： **其一**，make up会自动创建.env并生成其中 **15 个密钥** （凭证库、会话签名密钥、5 组服务间凭证、4 个数据存储密码），再创建管理员并把密码打印出来——密码在你机器上生成、只显示一次、不存任何地方，弄丢了make bootstrap ARGS=--reset-password再铸一个。 **其二**，端口被占不停装：自动换空闲端口、报出占用者、控制台地址跟着走，官方实测 5432 和 11434 双双被占的裸机上 **64 秒** 进到登录后的控制台。 **其三**，没有 Docker 也能跑：pip install aisoc-sandbox && aisoc-sandbox demo离线把一条告警走完整个智能体漏斗，30 秒以内；连机器都不想开，GitHub Codespaces 里make up同样能到。 **其四**，没装过就跑make doctor，它是逐个“查询”数据存储本身来体检，而不是问容器活没活，然后直接打印下一条该跑的命令。

装完第一件事，别急着接生产数据——在设置向导里点 **Load sample data**，五类场景从低危排到危急，走的是和真实连接器完全相同的 ingest 通道（不是往库里插行），所以“看着它们变成告警”就等于“看着流水线在工作”。故意从低排到高也有讲究：第一次运行就满屏危机，什么都教不了你。这些示例告警在来源列标着aisoc_sample，拒绝加载进已有真实告警的租户，也不会替你把安装标记成完成。想验证流水线本身，跑make smoke：

$ make smoke

\[PASS\] raw telemetry accepted by ingest

\[PASS\] event traversed the spine and became an alert

PASS: 10/10 stages

一条真实事件穿过 Kafka、检测、关联、Postgres、公共 API 回读，10 个阶段逐个报 PASS 或 FAIL。接真实数据两步：make ingest-token拿推送凭证（租户信息就在 token 里，不用传 header），或者到 Settings → Connectors 里配 91 个连接器之一。日常三件套：make test（每个服务的单元测试）、make smoke（对着运行中的栈跑金管道）、make stats（重新清点 README 公布的每一个数字，对不上 CI 直接挂）。

| 命令  | 作用  |
| --- | --- |
| make up | 启动 core 档 16 容器，含本地模型与 CISA KEV 情报源 |
| make up-full | 启动 full 档 22 容器，加事件湖 / 实体图 / 全文检索 |
| make doctor | 体检：内存、磁盘、端口、逐个查询数据存储并给出下一步命令 |
| make smoke | 一条真实事件穿越全链路，10 阶段逐项 PASS/FAIL |
| make demo | 加载合成数据集（每行 is_synthetic=true，控制台带标签） |
| make stats | 重新清点 README 公布的每个数字，CI 强制一致 |

06

Honesty

最有意思的：把不体面的数字全公开

安全产品发布会的标准姿势：告警降噪 90%、误报清零。AiSOC 反着来：告警减少率同时公布三个数字—— **75.3%** （旧版分组口径）、 **33.3%** （生产密钥口径）、 **24.5%** （修复一个标识符后的检测形状队列，且这次修复是把分组收窄而不是放宽）。三个口径各带标签，谁也不覆盖谁。

这种“不体面优先”贯穿全仓库： **仓库现实** （REPOSITORY_REALITY）文档用 WORKING / PARTIAL / BROKEN / DEMO-ONLY / DEAD CODE / DOCS-ONLY 七级给每个组件定性，审计日期、运行环境、复现命令全部写明；文档里自曝旧版快速开始“九个服务的 compose 没有 ingest 服务、Kafka 被禁用，控制台里的 15 条事件是脚本直接插进 Postgres 的”——用户看到界面以为是平台在跑，其实从来没跑过，这个审计把这件事钉在了文档里。截图目录的 README 写清每张图怎么拍的；成熟度表里“Stable”资格由 CI 门禁强制（发现过三行描述了不存在的覆盖之后加的）。每张评分卡写明实际服务的模型、样本分母公布、弃权和失败都计入恶意样本分母、测不了的写 not measured。

07

Boundaries

它不装什么都能干

不是 SIEM 替代品

它做关联和调查，不做长期日志留存和合规检索——这块该留给 SIEM 或数据湖，官方文档明确划了界。

看不见你没接的数据

没有自动发现。它对你没接入的遥测一无所知，也就不会给你“全网覆盖”的错觉。

默认不自治

响应需要显式策略授权加人工批准。演示事件和样本事件不是真实事件，基准数字是底座自洽性度量，不是线上智能体准确率——所有发布处都带标签。

写在最后

这个项目真正值得抄的不是 2966 条规则，也不是那个本地分诊模型，而是一种工程态度：“可执行”必须被证明，“Stable”必须有门禁，测不了的数字写 not measured。安全行业最不缺的就是漂亮演示，最缺的就是这种把审计文档写在自己 README 里的坦诚。

Agent 进安全运营是大势，但这条路怎么走才不翻车——让 AI 只碰类型化工具、判决必须可引用、动作必须过批准——AiSOC 给出了一份可以直接参考的工程答卷。后台回复关键词20261108获取项目地址。
