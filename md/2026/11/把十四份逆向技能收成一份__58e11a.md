> 新建了一个仓库 [https://github.com/ip2867/ctf-re-skills](https://github.com/ip2867/ctf-re-skills) ，里面是我做逆向题这段时间攒下来的十四份技能和六十五篇条目。这篇说一下为什么要把它们重新组织一遍。

前段时间我在三个不同的晚上打开同一份技能文件，每次都从第一段重新读。

第一次是查 z3 的查表怎么写，第二次是查 Feistel 怎么降维，第三次只是想知道「反调试应该先试什么」。三件事在不同章节，我得滑到不同位置，中途还会被别的内容分散。

这些文件本身没写错。问题在于它们按题目类型分，而我拿到一道题的时候，脑子里想的往往是下一步该干嘛，不怎么关心这题归哪一类。

## 一份总纲，十三份专项

新的结构是这样。 `skills/ctf-reverse-total/SKILL.md` 是全流程总纲，其余十三份还是原来的专项，内容没动。

总纲的写法跟专项不一样。专项讲这类题怎么做，总纲讲现在这一步该做什么。它开头就是三条原则，然后是一张判型表，接着按顺序讲结构检测、解密文、认算法、选求解器、下断点、验证。第十六章是一张按症状查的表，十四行，卡在哪查哪。

分工之后，读法变简单了。拿到题先看总纲，中途需要某类题的细节再翻专项。那三次翻同一份文件的情况不会再出现。

## 知识的组织方式

写总纲的时候我一直在处理一个问题。同一件事在专项里写得很细，在总纲里只能写三行，怎么写这三行。

我的做法是只保留「不做会失败」的部分，把操作步骤留给专项。

举个例子。z3 里把 256 字节 S 盒展开成 If 树，必须用 `ULT` 做无符号比较。写成 `If(v < k, left, right)` 的话，z3 按有符号解释，索引大于等于 0x80 全变成负数，前一百二十八项全查错。外部表现是约束明明有解却报 unsat，从报错里完全看不出原因。

这条在专项里有一整段解释，总纲里只有一句警告加一句正确写法。够用。

另一些内容反过来，总纲里比专项更长。比如三轮 Feistel 的换元。这个推导不写出来，光说「用 t = U^V^W 降维」等于没说，因为读者不知道 t 是怎么来的，也不知道为什么降完就能搜。所以总纲里把三条等式和判据都摆出来了，还注明 g 的逆里 k 要在最外层异或回来，写反了会一直找不到解。

判断标准就一条。读者看完这三行，能不能自己动手。

## 几条写进总纲的东西

整理过程中我挑了几条特别容易踩的，单独说。

**自洽不等于正确。** 这条是我在 license 那道题上花了很久才想明白的。当时常数 K0 和 K1 是从静态文件里读的，但那一段在运行期才解密，静态读到的是密文。用错常数算出来的 flag 是错的，可正向回代完全通过，因为回代用的是同一套错常数。整个链条内部一致，外部全错。后来必须拿原程序跑一遍才算验完。

这类错误没法靠自查发现。只能跟外部对拍。

**C 和 Python 差一百三十倍。** 同一个 2 的 32 次方搜索，C 加 `-O3 -march=native` 跑十八秒，Python 加 numpy 要四十分钟。这个数字我一开始不信，自己测了一遍才接受。所以 `arx_solve` 生成的是自包含的 C 源码，不是 Python 脚本。

**链式 XOR 不是自逆的。** 这个概念很容易记错，因为它长得像普通的 XOR。定义是从末尾往前，每一步用累加过的明文当下一轮的 key，索引零保持不动。拿解密函数当加密函数用会得到错的结果。我写测试的时候踩过一次。

**单步异常驱动的 VM 不能用 ptrace。** VM 自己要收 SIGTRAP，ptrace 会先截走，程序直接崩。得改用 `/proc/<pid>/mem` 轮询，以十六字节为单位反复读，只记变化的块。

## 知识库里那六十五篇

`wiki/` 下的条目分两类，我一直没改这个结构。

方法论页有十一篇，文件名叫 `method_*.md` ，每篇开头带 YAML 元数据，里面有三个字段我一直在用。

`attack_chain` 是解法链，按顺序列这条路的每一步。 `reasoning_chain` 记的是当时的推理，为什么从这一条想到下一条。 `failed_attempts` 是最有用的一个，记的是走不通的路和原因。

比如 `method_structure_before_algorithm.md` 里的 `failed_attempts` 有七条，其中一条是「页尾按整段平均判数据，零填充稀释，非零比只有百分之十三，漏判」。这句话背后是我第一次写那个检测时漏掉了真正藏着的代码。

赛事条目五十多篇，从 D3CTF、强网杯到各级比赛。每篇记的是这题卡在哪、怎么破的，不是流水账。这些条目平时不太翻，但遇到同类题的时候，能省掉重新摸索的时间。

## 怎么用

支持 Agent Skills 格式的工具可以直接把 `skills/` 指过去，每个目录下是标准的 `SKILL.md` ，带 frontmatter。

不需要工具的话，想看总纲就打开 `skills/ctf-reverse-total/SKILL.md` ，想查具体手法就翻 `wiki/` 。纯 Markdown，没有任何运行时依赖。

这批文件是 [CTF-RE-TOOL](https://github.com/ip2867/ctf-re-tool) 的知识层。那个工具负责调度 IDA、JEB、Frida、z3 这些执行能力，这里的文件负责告诉模型什么时候该用什么。两边分开之后，知识库可以单独更新，工具也可以单独发版本。

## 一点没做完的事

总纲目前十六个二级章节，一万六千多字节。我原本想压到一万以内，试了几次放弃了。

压缩不掉的是一些必须写全的判据。比如 ELF 那八类结构异常，每一类都要写清判据和意味着什么，少一行就变成「看到异常就试试」。又比如 Z3 那十二个坑，每一条都是独立的知识点，删哪条都会有人踩。

还有一个问题没解决。总纲按「下一步做什么」组织，但实际做题的时候经常是并行的，结构检测和字符串搜索可以同时做，解密文和认算法也可能互相印证。现在的线性结构是简化过的。以后可能会加一节讲哪几步可以并行。
