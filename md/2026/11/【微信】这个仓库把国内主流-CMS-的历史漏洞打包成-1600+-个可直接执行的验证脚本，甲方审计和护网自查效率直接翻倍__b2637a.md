**棉花糖网络安全工具箱** *2026年11月8日 10:55*

## 重点导读项目定位

poc 是一个历史漏洞验证脚本的汇总仓库，收录了 2013 至 2016 年间针对各类 CMS、OA 系统、电商平台与中间件的公开漏洞利用验证代码。

仓库本身不提供扫描调度、任务编排或结果聚合能力，它的定位是漏洞验证素材库：为安全测试人员提供可直接运行、可二次修改的单点验证脚本。

规模方面，仓库共提交 1637 个 Python 源文件，覆盖 6 个不同的漏洞扫描框架目录，单目录体量最大的 bugscan 收录了 1222 个 exp 脚本。

## 重点导读目录结构

```python
poc/
├── beebeeto/      # Beebeeto-framework 格式，318 个文件
├── bugscan/       # BugScan 格式，1225 个文件
├── bugscan_jiami/ # BugScan 混淆版本，87 个文件
├── kspoc/         # KsPoc 框架，含 comm 公共模块
├── pocsuite/      # PocSuite 格式
├── tangscan/      # TangScan 格式
└── common.pyc     # 编译后的公共模块
```

除源码外，仓库还提交了一个 241 KB 的 common.pyc 编译产物，为部分脚本提供跨框架共享的辅助调用。

## 重点导读六大模块

### PART 01beebeeto

采用 Beebeeto-framework 规范的模块，文件以 poc\_年份\_编号.py 命名，编号覆盖 poc_2014_0001 至 poc_2014_0224 以及 134 个 2015 年新增脚本。

每个脚本以 BaseFrame 子类的形式实现，poc_info 字典固定划分为 poc、protocol、vul 三个区块，poc 区块记录漏洞编号、名称与作者信息，protocol 区块声明协议类型、端口与传输层协议，vul 区块记录应用名、受影响版本、漏洞类型、标签与参考链接。

验证逻辑集中在 verify 类方法中，返回带 success 标志与 poc_ret 结果集的参数字典，并习惯性通过 exploit = verify 建立别名，让同一份代码同时承担检测与验证两种语义。

对二进制资源型漏洞，该模块统一采用 MD5 指纹比对手法：请求目标静态文件后计算哈希值，与硬编码的指纹常量比对，命中即判定漏洞存在，避免了响应内容解析的脆弱性。

### PART 02bugscan

体量最大的模块，全部脚本采用 exp-编号.py 的扁平命名，内部结构统一为 assign 与 audit 两个函数。

assign 函数负责按 service 标识进行目标分派，匹配成功时返回布尔值与目标地址元组，不匹配则直接返回空值。

audit 函数承担实际的漏洞探测，通过 curl.curl(url) 发起请求并解包出状态码、响应头与响应体三元组，再依据响应特征判定漏洞类型，例如检测 phpinfo() 页面标题以识别信息泄露。

判定成功后调用 security_info 或 security_hole 上报结果，这一对函数构成了该框架的结果出口。

脚本中出现的 service 标识反映出目标分布的偏好，覆盖了 wordpress、joomla、discuz、qibocms、hanweb、phpcms、weaver_oa、tongdaoa、metinfo、dedecms、ecshop、shopex、yongyou 系列等多个主流系统。

### PART 03bugscan_jiami

针对商业扫描器驱动的脱壳备份目录，87 个文件全部采用 exp－back\_编号.pyc_dis.py 命名，扩展名后缀表明这些是经过解包处理的 Python 字节码反编译结果。

代码结构保留了原脚本的骨架，但标识符被大规模替换为无意义符号，字符串常量改为十六进制转义形式，实际的 URL 路径与匹配特征需要通过解码函数还原。

目录下的 decode.py 给出了对应的还原算法：先由密钥逐字节异或运算生成轮转密钥，再按位统计结果动态决定位移位数，通过移位与掩码组合完成单字节变换，最后将还原结果与密钥一并追加写入 /opt/bugscan/libs/key.txt。

该目录还包含一个 info.txt 文件。

### PART 04kspoc

体量最小的框架模块，包含一个具体的 Discuz Flash 跨站脚本脚本，以及 comm 公共包。

comm 包下由 generic.py、cmdline.py 与 charsetck.py 组成，分别承担输出格式化、命令行解析与字符集探测。

框架定义了统一的 io_info 字典协议，字段涵盖 URL、Mode、Verbose、Error、Status 与 Result。Mode 取 v 表示检测模式，取 a 表示攻击模式；Status 取 1 表示利用成功，0 表示失败；Result 为二级字典，用于承载分项验证信息。

generic.output 负责将 io_info 渲染为带 Success、Failed、Target、Mode 前缀的文本输出，generic.modify_headers 负责构造默认请求头，并允许通过 X-User-Agent、X-Referer、X-Cookie 三个可选键覆盖默认的 User-Agent、Referer 与 Cookie。

单条脚本通过 cmdline.main 完成参数装配后进入 main 函数，最终以调用 generic.output 结束整条链路。

### PART 05pocsuite

仅收录一个 Git 信息泄露脚本，采用 PocSuite 的 POCBase 基类范式。

脚本通过 \_verify 与 \_attack 两个方法实现检测与利用分离，两者内部可共享同一段验证代码，最后交由 parse_attack 统一转换为 Output 对象并调用 register 完成注册。

验证逻辑为请求 /.git/config，若响应中包含 \[remote "origin"\] 特征串即判定为源码可被下载。

### PART 06tangscan

同样收录单个脚本，验证方向为 Flash 的 crossdomain.xml 跨域策略配置。

脚本继承 TSExploit 基类，通过 register_option 声明 url 参数并附加 convert 校验，通过 register_result 预置 status、data、description、error 四项结果结构。

判定逻辑先取 /crossdomain.xml 响应，确认存在 cross-domain-polic 特征后交由 minidom 解析 XML，逐个读取 allow-access-from 节点的 domain 属性，一旦发现通配符 \* 即判定为存在跨域策略缺陷。

## 重点导读漏洞覆盖

从 beebeeto 模块的元数据统计，SQL 注入以 78 条居首，其后依次为信息泄露 36 条、跨站脚本 35 条、代码执行 24 条、任意文件下载 23 条，另有文件上传、命令执行、本地文件包含、任意文件读取等类型。

目标系统方面，Discuz 相关脚本数量最多，WordPress、PHPCMS、phpwind、织梦、Joomla、U-Mail、Elasticsearch、易想团购、齐博 CMS、ECShop 等系统均有覆盖。

## 重点导读编写规范

各模块在长期演进中形成了稳定的共性写法。

元数据头部集中声明，漏洞编号、名称、作者、披露时间、创建时间与更新时间等字段位于脚本顶部，便于外部工具解析。

验证与利用分离，检测逻辑与利用逻辑保持独立方法或独立函数调用关系，同一份特征判定逻辑被两侧复用。

特征判定优先采用内容比对，字符串包含匹配、哈希指纹比对、XML 结构解析是三种主要手段。

返回结构统一，成功标志、错误信息、结果集合与详细输出开关构成固定的参数字典，调用方无需针对单个脚本做特殊处理。

依赖层面，脚本普遍基于 Python 2 语法，使用 urllib2、md5、print 语句等早期接口，运行前需具备对应的解释器环境与框架依赖。

## 重点导读合规提示

仓库内容对应的漏洞多数已公开多年，相关系统或组件普遍已完成版本迭代，历史漏洞的存在不代表当前线上版本必然受影响。

使用前应确认目标系统的实际版本，并确认测试已获得资产所有方的书面授权。
