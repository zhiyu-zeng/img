2026年10月23日，WhoisXML API 正式推出全新升级版网站分类（Website Categorization ）服务。

此次升级对网站内容分类方式、数据查询速度以及分类数据的应用集成能力进行了全面优化，旨在更好地满足广告技术（Ad Tech）、品牌安全、网络内容过滤及网络安全等领域的实际需求。

新版本引入了 IAB Content Taxonomy 3.1（IAB 内容分类标准 3.1），支持更丰富的分类结果、更快速的缓存查询，以及更加灵活的数据输出和集成方式。

对于现有客户，原版本可继续使用至2027年1月21日；新客户则可以直接使用升级后的版本。

**一、什么是网站分类？为什么它如此重要？**

网站分类的核心功能，是识别并判断一个网站所包含的内容类型。

这一看似简单的功能，实际上支撑着互联网浏览过程中大量重要的后台决策。

例如：

-   广告投放平台： 根据网站内容类别，判断是否适合展示特定广告，避免广告出现在成人内容、赌博或其他不适宜的网站上，从而保障广告投放环境和品牌安全。
    
-   企业网络管理： 企业可以利用网站分类信息，制定网络访问策略，对不符合内部管理规定的网站类别进行限制或屏蔽。
    
-   网络安全产品： 安全网关、DNS过滤系统及终端安全产品可以借助网站分类数据，更有效地识别和管理不同类型的网络访问行为。
    

此次网站分类的升级，正是为了让这些应用场景获得更加准确、高效和灵活的数据支持。

![图片](https://cdn.jsdelivr.net/gh/zhiyu-zeng/img@main/img/2026/11/7bb7a7468d97dccb.jpg)

**二、采用标准化分类体系：全面支持 IAB Content Taxonomy 3.1**

本次升级的一项重要变化，是原生支持IAB Content Taxonomy 3.1（IAB内容分类标准 3.1）。

IAB分类体系为描述网站内容提供了一套通用标准，广泛应用于数字广告、程序化广告和品牌安全管理等领域。

通过采用这一最新版本的分类体系，WhoisXML API能够直接按照统一的行业标准对网站内容进行分类，进一步提升分类数据的规范性和兼容性。

新版本主要支持以下功能：

-   704个分类类别： 完整支持 IAB Content Taxonomy 3.1 中的全部704个分类类别。
    
-   四级分类结构： 支持完整的四层分类体系，帮助用户从不同层级理解和识别网站内容。
    
-   多类别识别： 每个网站可返回一个主要分类，并支持最多两个备选分类。
    
-   丰富的分类信息： 提供分类 ID、分类名称、分类路径以及置信度等信息。
    

对于已经采用IAB分类标准的广告平台和其他业务系统而言，这意味着网站分类能够更加自然地融入现有工作流程，降低数据适配和系统集成的复杂程度。

**三、查询速度全面提升：让网站分类更加高效**

当网站分类功能被应用于实时业务场景时，查询速度尤为重要。

以企业网络过滤为例：当员工访问某个网站时，安全产品需要迅速判断该网站是否符合企业的网络访问政策。如果分类查询耗时过长，就可能影响用户的正常访问体验。

为此，全新升级的网站分类API引入了缓存机制，显著提升重复查询的响应速度。

主要优化包括：

-   缓存查询： 对于已有缓存的查询结果，响应时间可缩短至1秒以内。
    
-   实时分类： 对于需要重新进行分类的请求，通常只需数秒即可完成。
    
-   灵活控制缓存： 对于需要获取最新分类结果的应用，可选择绕过缓存机制。
    
-   支持直接提交网页内容： 用户可以直接提供网页标题、描述或正文内容，跳过系统获取网站内容的步骤，从而进一步缩短分类处理时间。
    

这些改进使网站分类服务能够更好地适应实时访问控制、广告投放审核以及大规模网站内容识别等对响应速度要求较高的应用场景。

**四、更加丰富的数据输出，满足多样化业务需求**

除分类标准和查询速度之外，新版本还进一步扩展了网站分类的数据输出形式和应用方式。

根据不同业务场景，用户可以灵活选择所需的数据类型和调用方式。

**1\. 更丰富的分类结果**

除了主要分类，新版本还可提供最多两个备选分类、分类置信度、分类体系详细信息，以及数据来源和数据时效性信息。

这些信息有助于用户更加全面地了解分类结果，并根据实际业务需求进行判断。

**2\. 支持47种策略分类组（Policy Groups）**

针对 DNS 过滤、安全 Web 网关（Secure Web Gateway）和终端安全工具等应用，新版本支持请求47种策略分类组。

相比单纯的网站内容分类，策略分类组能够从更贴近实际安全管理的角度提供分类信息，帮助企业制定更加全面的网络访问和安全管理规则。

**3\. 支持 OpenRTB 数据输出**

新版本支持以兼容OpenRTB的格式返回网站分类信息。

OpenRTB是程序化广告交易领域广泛使用的开放技术标准。这一功能有助于广告平台及相关系统更便捷地将网站分类数据应用于程序化广告和广告交易工作流程。

**4\. 支持预测分类集合（Prediction Sets）**

当应用场景需要考虑分类结果的不确定性时，用户可以根据选定的覆盖水平，请求获取一组具有合理可能性的分类结果。

这一功能能够帮助业务系统在处理复杂网站内容时，更充分地考虑分类判断中的不确定性。

**5\. 支持单条及批量 API 查询**

用户既可以一次查询一个域名，也可以通过单次请求对最多100个域名进行分类。

这为不同规模的业务需求提供了灵活的调用方式。

**6\. 提供批量数据订阅（Bulk Data Feed）**

对于需要大规模网站分类数据的用户，WhoisXML API 还提供批量数据服务。

数据每周提供一次完整快照，并通过每日增量更新持续补充数据，支持压缩CSV和Parquet格式。

近期一次完整数据集已包含超过 1.64亿条域名记录。这意味着用户不仅可以通过 API 实时查询单个网站的分类信息，也可以将大规模网站分类数据直接整合至自身系统，开展持续性的数据分析和业务应用。

**五、升级新版本需要注意哪些变化？**

全新的网站分类在功能和技术架构升级的同时，也带来了一些需要客户关注的接口调整。对于现有客户，原版本可以继续使用至2027年1月21日，为系统升级和接口迁移预留了准备时间。新客户则只能使用新版本。

WhoisXML API建议现有客户在2027年1月21日之前完成接口更新，以避免后续业务中断。此次迁移中，API Key和网站分类的服务域名保持不变，但以下几个方面需要特别注意：

**1\. API 请求格式发生变化**

新版本采用：POST /api/v4/categorize

请求时需要通过 JSON 请求体传递待分类的域名。

**2\. 分类体系更新**

新版本采用 IAB Content Taxonomy 3.1 分类体系，返回对应的 IAB v3.1 分类 ID 和层级信息。如果现有系统仍然基于此前的分类 ID 建立业务规则，就需要相应调整和更新，以适配新的分类体系。

**3\. 返回数据字段有所调整**

新版本的网站分类响应将更加聚焦于网站内容分类本身，不再返回 ASN 和 WHOIS 创建日期等字段。如果客户仍然需要这些信息，可以通过 WhoisXML API 对应的专业数据服务获取：

-   IP Netblocks API：用于获取 IP 地址段及相关网络信息。
    
-   WHOIS API：用于查询域名注册信息，包括 WHOIS 创建日期等数据。
    

有关接口迁移和具体技术要求，可参考官方 API 文档。
