## 红队把智能体搬进浏览器15 分钟打穿内网的剧本已上演

真实入侵里已经出现 AI 智能体跑完整攻击链——甲方蓝队得重新学怎么守。

AI 渗透甲方防御机器速度

● **一句话精华**  
攻击者的节奏已经变成“机器速度”，可不少甲方的防守还停在“人工排期”。技术没变，变的是节拍。

最近圈里看到一款“打开浏览器就能让智能体做渗透”的插件——不用开什么工具，不用配环境，一个 Chrome 加 Node.js，就能让 agent 在浏览器里直接对目标站点下手。看着像极客玩具，但 2026 年 10 月 30 日 Google Threat Intelligence（GTIG）和 Mandiant 联合发的一份报告，把这事从“玩具”拽到了“实战”：真实入侵里已经出现用 AI 智能体跑完整攻击链的案例，从拿到一个被盗账号到拿下深层系统权限，最快只用了 15 分钟。

红队把智能体搬进浏览器，甲方这边真得重新想想怎么守。

## 01为什么这事对甲方是“大事”，不是“玩具”

很多人觉得“AI 渗透”离自己远，其实是三件事同时发生了：

-   攻击门槛又又又塌了。
    
    以前搞渗透，得懂工具、配环境、写脚本，门槛不低。现在主流思路是给 agent 一个“目标 + 目标”，它自己选工具、执行命令、看报错、换方向继续。从最早的 ReACT，到后来的 Harness、DAG 黑板工程，本质都是把“人操作”变成“机器自主”。圈里有人早就搓出了浏览器端的 MVP，把最顺手的框架融进去，重计算丢给后端，浏览器里只管操作和调度——普通人也能上手。
    
-   速度变成了机器速度。
    
    报告里点名的 ARTEX 这类多智能体平台，把攻击生命周期拆给 6 个子智能体并行跑。它的执行是一波一波的爆发：单波 2 到 25 秒，曾在 23 秒里探了 27 次 AWS 权限。你还在排期做人工渗透，对手已经不按小时算了。
    
-   难的不是招式，是节奏。
    
    Mandiant 反复强调：这些智能体用的技术本身一点都不新，还是盗凭证、打暴露面、内网横移、准备渗出那一套。变的是“自动化把时间压扁了”。因为它走的是合法凭证和合法功能，传统特征检测和静态规则会大面积静默——你看着一切正常，其实钥匙早被人拿走了。
    

## 02智能体渗透是怎么打甲方的（攻击链拆给你看）

把真实案例里的打法拆开，甲方最该盯的是这几步：

-   入口：你忘了关的那扇门。
    
    暴露的 Web 应用、管理后台、弱口令、被盗凭证（OA、VPN、云控制台），是智能体最先咬住的地方。它不需要 0day，有合法入口就够。
    
-   浏览器 agent 的特殊威胁：它像人一样点页面。
    
    普通红队工具走流量、走协议，WAF 和 NDR 看得见特征。可浏览器里的 agent 是直接“看页面、点按钮、填表单、读返回、调接口”，整个交互就是真人 UI 操作。传统基于流量的防御，对“人模样”的操作天然不敏感。
    
-   横移：拿到合法身份后自动扩权。
    
    一旦有了凭据，agent 会自动去探这个身份能干什么——调 Azure 的 Kudu 管理 API 跑命令、用 AWS IAM 的 dry-run 探权限、Kerberoasting、DCSync 偷域控 key，甚至一口气枚举 11 万多个 AD 对象。全程用的都是系统自带的功能。
    
-   渗出：用你自己的功能打你。
    
    有案例里，agent 用应用自己的 SQL API 把日志指向一个网页可访问的 jsp 文件，再用 SELECT 语句把 webshell 写进去；还把命令结果回传到一批轮换的 webhook 地址，甚至借用应用的内部通知系统给上千名内部员工发测试邮件。它不是“攻破”了什么，是“借用”了你的能力。
    

一句话总结：智能体攻击最可怕的地方，是它不破门，它拿着钥匙进门。

## 03甲方蓝队怎么“看见”智能体攻击

特征检测会漏，但行为不会完全藏住。蓝队要把视线从“特征”挪到“行为”：

-   盯“身份速度”和“API 突发”。
    
    合法凭证 + 合法功能 = 传统规则静默。但机器操作有机器特有的节奏：一个账号几秒内疯狂调权限接口、短时间内枚举海量 AD 对象、批量创建管理员或云实例——这就是“身份速度（identity velocity）”和“API 突发（API burst）”。把它们写进 SIEM/NDR 的检测规则，比堆特征有用。
    
-   吵，反而是机会。
    
    ARTEX 一点都不 stealth，它很“吵”：留下 artex-probe-\* 命名的文件、名字里带 ArtexProbe 的账号、几百毫秒内写进去又删掉的测试 blob、往外连 webhook.site 的流量。一次 SQL 注入尝试就刷出 240 条日志。对防守方来说，这种噪声恰恰是溯源的抓手——它暴露了自己。
    
-   别忘开发机这个跳板。
    
    2026 年 10 月 29 日 EMBRACE 研究证实：几款主流 AI 编程助手的内置浏览器能被恶意网页劫持，去读项目外文件、甚至跑本地命令。装了 SSH 密钥和云凭证的开发电脑，一旦被智能体借道，就是新的内网入口。建议把“开发机凭据外泄面”也纳进暴露面盘点。
    

## 04甲方能不能用 AI 自己做“自查”？能，但三条线不能碰

红队用智能体打，甲方当然也能用智能体“以攻促防”。但工具作者自己都写了大字免责：只准在你拥有所有权、或取得书面授权的系统上跑；指向别人的系统，那不是测试，是违法。从甲方合规角度，再加三条硬线：

-   授权线。
    
    自查只在自己资产上做；把工具指向客户、供应商、第三方，哪怕“想看看”，也踩了法律红线。出了事，责任 100% 自己扛。
    
-   范围线。
    
    用 AI 渗透平台时，白名单范围校验必须开（任务一旦越界立即拦截），不要给平台超出授权的凭证。范围失控，自查就变成误伤。
    
-   数据线。
    
    优先选“数据零留存（ZDR）”的平台，测完不留痕；别把生产凭证喂给来路不明的开源 agent。
    

好消息是，国内合规化的 AI 渗透能力已经起来了：有平台接了多个经实战检验的红队智能体做交叉验证、支持 ZDR；也有厂商的 AI 攻防平台在实战演练里 7 小时测了 5 万多资产。甲方自查正从“预约排期、等报告”走向“常态化 7×24 持续验证、一键复测”。工具是平的，关键是你敢不敢把自己的家底先摸清楚。

## 05给运维和安全负责人的 5 步落地清单（直接能抄）

-   ① 收暴露面。
    
    先把互联网侧暴露的 Web 应用、管理后台、API、公网端口盘干净。智能体最爱的，就是你忘了关的那扇门——这一步呼应我们反复说的“影子资产”问题。
    
-   ② 管凭证卫生。
    
    淘汰长期静态密钥，换成短时效的工作负载凭证或角色；开发机上的 SSH 密钥、云凭证单独隔离，别和日常账号混用。
    
-   ③ 最小权限 + 网段隔离。
    
    把管理 API、控制台、CI/CD 收进受信网络；做好分段，断了横移的路。合法凭证再厉害，也得出不了段。
    
-   ④ 补行为检测。
    
    在 SIEM/NDR 里加“身份速度 + API 突发 + 非人类交互节奏”规则，别只靠特征签名。看得见，才拦得住。
    
-   ⑤ 常态化自查。
    
    用合规的 AI 渗透平台做 7×24 持续验证，高危漏洞一键复测，把“发现—修复—复测”的闭环真正跑起来。

▲ 把这几件事今天排进待办，比等“更隐秘的全自主攻击”来了再慌强

## // 老宋说

用智能体打渗透，不是“黑客突然变厉害了”，是“攻击开始用机器速度跑”。甲方别慌，但也别装看不见。技术本身没变，节奏变了——把暴露面收干净、把凭证管严、把行为检测补上，这三件事今天就能动手。

等报告里说的“全自主、更隐秘”的下一阶段来了，你手里那张活地图和那套行为规则，才是真正的护城河。到那时，比的不是谁工具新，是谁家底清、防得住。
