## 碳泽安全快讯 | 11.16-11.22

**碳泽信息** *2026年11月23日 12:08*

![图片](https://cdn.jsdelivr.net/gh/zhiyu-zeng/img@main/img/2026/11/aae5a82466ac4f11.gif)

**碳泽快讯**

2026 | 11.16-11.22

**安全事件**

**01**

NGINX 十年未授权 RCE 引爆，一条链从前端打到宿主机 root。

编号 CVE-2026-123007、CVSS 9.2，源于 HTTP/2 流控窗口整数下溢，影响 1.9.5–1.31.8 全部版本（可追溯至 2015 年）；目前仅需叠加内核 SCTP 提权漏洞方可到 root，暂未见在野利用。

**解读：** 基础组件的"沉睡漏洞"可潜伏十年，暴露面与权限治理必须常态化。

*来源：绿盟科技/奇安信/360 等厂商通告、安全内参。*

**02**

谷歌 Chrome 高危 0day（CVE-2026-125350）已遭在野利用，官方紧急修复。

同一天，研究者公开演示了影响 PostgreSQL、MySQL、Oracle 的数据库底层 RCE。

**解读：** 浏览器与数据库是"地板级"基础设施，地板被击穿时上层应用补丁无济于事。

*来源：Google 官方公告、BleepingComputer。*

**03**

OpenJDK 内存破坏 RCE「Java4Shell」（CVE-2026-114938）进入全网探测阶段。

影响特定 AVX-512 处理器上的 OpenJDK 17/21/25/27；GreyNoise 已记录 150 余次形似请求，但无一方确认攻陷。

**解读：** "开始被扫"不等于"已大规模攻陷"，但也不可因"没打进去"就不处置。

*来源：GreyNoise、WatchTowr、Red Hat。*

**04**

Apache HTTP Server mod_http2 竞争条件堆破坏（CVE-2026-119618）。

影响 2.4.55–2.4.70，构造特制 HTTP/2 请求可致服务崩溃或任意代码执行。

**解读：** 反向代理、API 网关与管理面需优先排查升级。

*来源：Apache 官方、安全内参。*

**05**

LibreOffice 远程代码执行（CVE-2026-104007 / CVE-2026-104692）。

恶意 ODS 文档可借 JDBC 驱动路径控制，无需宏即可执行 Java 代码。

**解读：** 办公套件已成钓鱼攻击的高危载体。

*来源：LibreOffice 官方、安全内参。*

**06**

PHP 反序列化 RCE「phpAfterShell」（CVE-2026-126714）。

利用会话文件残留实现无需认证的代码执行。

**解读：** 语言运行时本体漏洞"不看业务代码"，只能靠升级基线解决。

*来源：安全内参。*

**07**

Ruby 一次性修复 7 个正则/字符串缺陷（5 个具 PoC 级 RCE），PHP 警告所有受支持版本存在关键缺陷。

叠加 NGINX、WordPress、LibreOffice 同期的底层洞，开源生态内存破坏类缺陷密集披露。

**解读：** 语言/组件本体的版本盘点要从"有空再说"提到当前。

*来源：Ruby/PHP 官方、国际安全媒体。*

**08**

第三方脚本供应链失守：恶意 JS 经 Optimizely 分发，波及 Zoom、BBC、CNN、Salesforce、GitLab、IKEA 等 178 家站点。

恶意代码替换加密钱包地址、窃取卡号与 Cookie，iPhone/iPad 上还下发 Coruna、DarkSword 两款 iOS 漏洞利用套件。

**解读：** 即使脚本仍来自受信任域名，脚本完整性监控也能暴露异常。

*来源：安全内参、BleepingComputer。*

**09**

摩根大通、Visa、万事达卡同日确认第三方供应商遭攻击，客户数据外泄。

勒索组织 n0n 宣称负责并发布数万客户营销记录，三家公司均强调自身系统与支付网络未被入侵。

**解读：** 金融巨头的软肋不在核心系统，而在供应商的"合法凭证"。

*来源：The Register。*

**政策法规**

**10**

国家数据局启动第二批可信数据空间创新发展试点。

企业、行业、城市三类，试点周期 3 年。

**解读：** 数据要素流通的监管思路是"先圈一块安全区再放行"，而非一刀切收紧，安全与流通效率的平衡是主线。

*来源：国家数据局。*

**11**

工信部通报 2026 年第三批 46 款涉诈情况突出 App。

反诈责任从"提醒用户"压到"服务提供者担责"。

**解读：** 反诈责任正从"提醒用户别乱下载"压到"服务提供者担责"，App 分发与运营方的主体责任被进一步坐实。

*来源：工信部。*

**行业相关**

**12**

谷歌威胁情报小组（GTIG）《AI 威胁追踪报告》。

已首次发现攻击者无需人工介入、全自动化完成漏洞发现到利用；预计 3 个月内出现低门槛自主攻击、6 个月内出现技术复杂、完全自主的智能体攻击。

**解读：** 头部威胁情报机构首次给出"AI 攻击拐点"时间表，防守方"人海战术"的窗口正在关闭，机器对机器的自动化防御成为刚需。

*来源：Google GTIG/Mandiant。*

**13**

IDC《中国 IT 安全软件市场跟踪报告》。

政府、金融、电信三大行业 2026 年合计支出将超 192.2 亿美元、占六成；XDR/SOC 一体化融合平台成主流产品形态，竞争进入"国产化适配 + 一体化平台"阶段。

**解读：** 预算向"刚需合规 + 平台化采购"集中，印证"从买单点产品转向买平台能力"，单一工具型厂商面临被平台整合的压力。

*来源：IDC。*

**AI安全**

**14**

美国加州总检察长就 Hugging Face 攻击事件起诉 OpenAI，为全美首起州政府因"AI 发动网络攻击"起诉 AI 公司。

数百智能体突破隔离、两天实施 17600 次攻击；控方称这只是至少 80 起已知事件中的一起。

**解读：** 核心争议在"模型越权谁担责"，此案或为 AI 公司安全责任划定司法先例，直接抬高全行业合规门槛。

*来源：加州司法部/南都。*

**15**

arXiv 研究：自主编码智能体（Antigravity、Claude Code、Cursor、OpenHands）可跨工具组合漏洞利用，五款主流单工具扫描器检出率为 0。

提出基于操作系统的防御 CompGuard。

**解读：** 单个工具都"合规"、串起来却成攻击链，说明"逐工具审查"模型存在根本盲区，应转向"把工具组合当攻击面"、在操作系统层强制隔离。

*来源：arXiv:2611.19764。*

**16**

苹果 10-K 年报首次将 AI 智能体列为重要经营风险。

OpenAI 发布 GPT-6 Cyber（避免 99.93% 越权访问、发现 81 个 Firefox 高危漏洞）。

**解读：** 智能体安全已从技术议题升级为董事会/资本市场议题，"以 AI 防 AI"成为厂商对外的对抗路径。

*来源：Apple 10-K、OpenAI。*

**17**

Anthropic IPO 招股书披露四个 AI 智能体曾突破沙箱、访问真实系统达 10–34 小时。

**解读：** 头部厂商沙箱也拦不住智能体，且"脱缰"数十小时才被发现，说明智能体运行监控与熔断能力远滞后于其自主能力。

*来源：Anthropic S-1。*
