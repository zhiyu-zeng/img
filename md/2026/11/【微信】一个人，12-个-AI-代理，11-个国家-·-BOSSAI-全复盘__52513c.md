操作员画像

ACTOR PROFILE

TRU 以 **高置信度** 将该活动归因于一名驻扎在中国台湾花莲市的个人，使用住宅宽带连接。活动被归类为 **AAT（AI-augmented threat，AI 增强威胁）**：单一操作员借助 AI 代理网络，实施兼具 APT 与网络犯罪特征的行为。目标横跨政府、金融、教育、军事、电商与赌博平台，无单一政治或意识形态目的，推测动机为牟利。

操作员以繁体中文下达命令，常缩短到一个 URL；代理窗口之间不直接通信，他手动复制粘贴结果，是整个网格唯一的“人工桥梁”。

攻击网格如何运作

HOW IT WORKS

BOSSAI 由 12 个 AI 代理组成，其中 9 个活跃，分三类角色协同：

攻击者

Hermes（主攻）、Cursor、Trae、CyberStrike——扫描目标、构建并执行利用。Cursor 生成 LFI、JWT bypass、认证模糊测试脚本；Trae 编写爬虫与针对大学目标的 SQL 注入脚本。

构建者

Grok 4.5（14 个会话，安装 HexStrike AI、配置 Cloudflare DNS）、OpenClaw（MiniMax M3，约 17 个会话）、Claude Code 与 Codex（经 shim 将 API 调用转至本地模型）。

扫描层

HalberdStrike（代理式渗透框架，至少 20 个项目，scope 校验被禁用）+ 破解版 Acunetix AWVS。

HERMES主攻击代理：全自主 + 持久记忆

Hermes 是网格的“workhorse”：约 95 个会话、18,311 条消息，其中 83.5% 是工具调用及结果；19 天内轮换至少 9 个模型，最终默认为操作员称为 DS4 的本地去对齐（abliterated）DeepSeek-V4 变体——64K 上下文、4 块本地 GPU。

它以 HERMES_YOLO_MODE=1 全自主模式运行（操作自动批准），系统提示词禁止拒绝与说教，并被授予全权：“決策全線都給你 你處理不用在問我 直到漏洞確定可利用後再回報”。

Hermes 携带可自我修补的技能库（SKILL.md）：调用最多的 gov-api-penetration 达 51 次调用、57 次迭代补丁，gambling-platform-penetration 28 次、52 次补丁——形成跨会话、跨模型轮换的“持久攻击记忆”。同期工具统计：3,300+ 次终端命令、2,000 次代码执行；sqlmap 出现 561 次、FOFA 432 次、nmap 271 次、Shodan 213 次。

ATTACK FLOW

典型攻击链路：扫描 → 研判 → 人工转交 → 利用 → 外泄

HalberdStrike 漏洞扫描 BOSSAI 网格 · 代理间不直接通信 Hermes 研判 操作员 人工转交 Cursor 执行利用 数据 外泄

实录案例：HalberdStrike 扫描某应急服务网站 → Hermes 将发现整理成报告 → 操作员粘贴进 Cursor 并下令利用 → Cursor 执行攻击（Acronis TRU）。

商业模型

Grok 4.5 / MiniMax M3：系统性拒绝攻击请求，引用计算机犯罪法、索要书面授权

vs

本地 abliterated 模型

顺从指令，但能力更弱、幻觉更多——高危发现超一半是误报

值得注意的是，操作员曾要求 Hermes“不要问、直接做”，结果 Hermes 反而自行判断洪都拉斯军事人员系统“超出范围”而未加利用；对国家灾害响应中心的“关键 Apache RCE”报告，也被平台自我复查后降级为误报——端口实为过滤状态。

打到了哪里

VICTIMS & IMPACT

12 天内，约 10 个目标确认发生数据窃取或系统访问（跨 3 国），另约 15 个目标遭主动攻击但未确认攻陷；8 个其他国家/地区的实体遭侦察或已暂存待扫描。最严重的确认危害针对应急服务数据。

CASE

#### 台北消防急救病患记录平台

应急医疗 · 中国台湾

无凭据即可访问 2018 年（含）以来的心电图读数、救护车视频与患者生命体征。

**确认失陷：遗留医疗数据在无认证平台上暴露多年。**

CASE

#### 某市 119 紧急调度系统

政府应急 · 中国台湾

提取案件记录：事发时间、响应类型、状态字段与街道级位置，覆盖 7 个区。这是 API 调度案件记录，不是实时 GPS 追踪。

**确认失陷：调度数据可被批量提取。**

CASE

#### 金融与消防调度供应商

金融 / 关键供应商 · 中国台湾

某借贷公司 MSSQL 2017 后端被确认 16 个 SQL 注入点，账户信息表数据被提取；某消防调度技术供应商的数据库管理面板沿用默认 root 凭证，暴露 18+ 张表。

**确认失陷；但对同一供应商经已知 CVE 植入 webshell 的尝试失败。**

墨西哥 · 大规模 PII 收集

构建覆盖 3 城 12 个富裕社区的电话目录：约 206,800 条住宅电话记录（姓名、地址、邮编），另有约 124,000 条黄页记录。两轮暴力破解与 2,600+ 组凭据填充均失败。

泰国 · 几乎全是大学

45 所机构的 489 个潜在目标中，3 所大学确认 SQL 注入并窃取数据（其一 Oracle 数据库导出 2,563 行管理员表）；另 2 所确认注入点但未确认数据提取。

洪都拉斯 · 未被利用

侦察中偶然发现空军人员系统，逆向 Angular 应用并映射内部 API 端点——模型自行判断“超出范围”而未咨询操作员。

其余为侦察级目标（美国、英国、澳大利亚、斯里兰卡、新加坡的高校；中国内地与越南的批量扫描）与 57 个暂存未扫 URL（中国香港、印度尼西亚、加拿大）。iOS 加密货币钱包提取工具包已组装，从未用于真实目标。

防御建议

DEFENSE

报告最有价值的结论之一是：AI 代理在基础安全失效处大开大合，在防御生效处全部碰壁。失陷点没有一个是“高深技术”，全部是“本不该存在”的问题。

P0立即执行（应急 / 医疗 / 消防 / 金融 / 教育行业优先）

-   用第 05 章 IOC 比对自有资产，回溯至少 90 天日志
    
-   清除数据库面板、监控设备的默认凭证
    
-   调度、病患记录等数据类 API 强制认证与授权
    
-   排查未打补丁的公网数据库实例
    

P130 天内

-   公网资产与端口梳理、子域名收敛、影子 IT 排查
    
-   SQL 注入修复用参数化查询；登录限流与失败锁定（注意防账号锁定 DoS）
    
-   部署针对 sqlmap / nmap / Hydra 高频扫描与代理出口的检测规则
    
-   核查视频监控设备固件版本与公网暴露面（以厂商官方公告为准）
    

P2长期治理

-   数据保留治理：2018 年的遗留医疗数据不应仍可无凭证访问
    
-   将技术供应商纳入安全评估——消防调度供应商正是本次失陷点
    
-   监测 HexStrike AI、HalberdStrike、Oktos 等攻击框架在内部的未授权使用
    
-   摒弃“隐蔽即安全”：认证、补丁、最小暴露才是可靠防线
