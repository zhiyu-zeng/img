**网络技术干货圈** *2026年11月8日 08:24*

信创迁移这两年最典型的场景：一台贴着麒麟标签的服务器推到你面前，或者一台麒麟桌面机交给你维护。你 SSH 进去， `ls` 、 `cd` 、 `ps` 、 `tail` 全都认识，心里一松——然后 `apt install` 报错， `yum install` 也报错， `systemctl stop firewalld` 说没有这个服务。

八成命令你都熟，剩下的两成坑就在这儿。这篇按功能分类整理高频命令，重点不是把 Linux 命令再抄一遍，而是把 **麒麟上多出来的、不一样的那部分** 讲清楚。

![图片](https://cdn.jsdelivr.net/gh/zhiyu-zeng/img@main/img/2026/11/5736d931f64506eb.png)

银河麒麟 V10 不是一个"版本号"，是 **两条产品线**，底座不一样：

| 对比项 | 桌面版 | 服务器版 |
| --- | --- | --- |
| 产品全称 | 银河麒麟桌面操作系统 V10 | 银河麒麟高级服务器操作系统 V10 |
| 底座  | Debian 系 | CentOS 8 系 |
| 包管理 | `apt` / `dpkg` | `yum` / `dnf` （后期版本以 dnf 为主） |
| 源配置 | `/etc/apt/sources.list` 及 `sources.list.d/` | `/etc/yum.repos.d/*.repo` |
| 包格式 | `.deb` | `.rpm` |
| 文件系统（常见） | ext4 | xfs |
| 系统日志 | `/var/log/syslog` | `/var/log/messages` |
| 登录/提权日志 | `/var/log/auth.log` | `/var/log/secure` |

**怎么快速判断**： `cat /etc/os-release` 看 `ID` 和 `PRETTY_NAME` ； `hostnamectl` 里的"操作系统"一行也会写明是桌面版还是服务器版；再 `which apt dnf yum` ，哪个在就基本印证了底座。

> ⚠️ **桌面版源自 Debian 系，服务器版源自 CentOS 8 系，但麒麟都做了大量定制。** 软件源地址、默认服务、部分工具路径、安全机制都和原生发行版不同。拿 Ubuntu 或 CentOS 的文档直接照套，八成能过，剩下两成足够你排查一下午。

## 一、系统与硬件信息查询

| 命令  | 说明  |
| --- | --- |
| `cat /etc/os-release` | 两版通用，看发行版标识 |
| `cat /etc/kylin-release` | 麒麟自己的版本标识文件 |
| `nkvers` | 麒麟专有，直接输出系统版本、内核、构建信息 |
| `uname -r` | 内核版本 |
| `hostnamectl` | 主机名、系统、内核一屏看完 |
| `lscpu` | CPU 型号、核数、架构 |
| `free -h` | 内存占用 |
| `dmidecode -t system` | 厂商、机型、序列号（需 root） |
| `uptime` | 运行时长与负载 |
| `timedatectl` | 时间、时区、NTP 状态（日志时间对不上先查这里） |

## 二、软件包管理

### 01桌面版：apt / dpkg

| 命令  | 说明  |
| --- | --- |
| `apt update` | 刷新源索引，装东西前先跑 |
| `apt upgrade` | 升级已安装的包 |
| apt install 包名 | 安装  |
| apt remove 包名 | 卸载，保留配置文件 |
| apt purge 包名 | 卸载并删除配置 |
| apt search 关键词 | 搜索可用包 |
| `dpkg -i xxx.deb` | 装本地 deb；缺依赖用 `apt --fix-broken install` 补 |
| dpkg -l \| grep 关键词 | 查已安装 |
| dpkg -L 包名 | 这个包装了哪些文件 |
| dpkg -S /路径 | 反查某文件属于哪个包 |

### 02服务器版：yum / dnf

V10 服务器版上 `yum` 和 `dnf` 基本可以互换，后期版本以 `dnf` 为主，下面统一写 `dnf` 。

| 命令  | 说明  |
| --- | --- |
| `dnf makecache` | 生成/刷新元数据缓存 |
| dnf install 包名 | 安装  |
| dnf remove 包名 | 卸载  |
| dnf update 包名 | 升级指定包，不带包名则全量升级 |
| dnf search 关键词 | 搜索  |
| dnf list installed \| grep 关键词 | 查已安装 |
| dnf provides \*/命令名 | **最实用**：查某条命令属于哪个包 |
| `dnf repolist` | 看当前启用的源 |
| rpm -ql 包名 | 这个包装了哪些文件 |
| `rpm -ivh xxx.rpm` | 装本地 rpm |

> ⚠️ **源不要混搭。** Debian/Ubuntu 的源文件不能搬到桌面版，CentOS 的 repo 也不能搬到服务器版。麒麟的源地址和签名密钥是配套的，混用轻则校验失败，重则依赖关系乱掉、系统起不来。桌面版尤其建议优先用系统自带的软件商店和更新管理器装软件。

## 三、服务与进程管理

`systemctl` 两版通用，这部分基本没有差异：

| 命令  | 说明  |
| --- | --- |
| systemctl status 服务名 | 看状态，动手前先跑这条 |
| systemctl start / stop / restart 服务名 | 启停重启 |
| systemctl enable --now 服务名 | 开机自启并立即启动 |
| systemctl disable 服务名 | 取消自启 |
| `systemctl list-units --type=service --state=running` | 当前在跑的服务 |
| `systemctl list-unit-files \| grep enabled` | 所有开机自启项 |
| journalctl -u 服务名 -f | 实时跟某个服务的日志 |
| systemctl cat 服务名 | 直接看 unit 文件原文，比到处找路径快 |
| `systemctl daemon-reload` | 手改过 unit 文件后必须执行 |
| ps -ef \| grep 关键词 | 找进程 |
| `kill -9 PID` / pkill 进程名 | 强杀  |

> 麒麟差异：系统里有一批 `ky` / `kylin` 开头的自有服务（安全、更新、激活相关）。动它们之前先 `systemctl list-units | grep -i kylin` 看清楚是什么， **安全相关的服务不要随手 disable**。

## 四、网络配置与排障

| 命令  | 说明  |
| --- | --- |
| `ip addr` | 看 IP（ `ifconfig` 已非默认安装） |
| `ip route` | 看路由表 |
| `nmcli device status` | 网卡与连接状态 |
| `nmcli connection show` | 列出所有连接配置 |
| nmcli connection up / down 连接名 | 启用/断开某个连接 |
| `ss -tunlp` | 端口占用，排"端口被占"必用 |
| `ping` / `traceroute` / `dig` | 连通性、路径、DNS |
| curl -I 地址 | 只看响应头，验 HTTP 服务 |

**配静态 IP，建议直接用 nmcli，别去手改配置文件** （手改容易漏字段，还容易被 NetworkManager 覆盖）：

```
nmcliconnectionmodify连接名ipv4.methodmanual\
ipv4.addresses192.168.1.10/24ipv4.gateway192.168.1.1\
ipv4.dns114.114.114.114
nmcliconnectionup连接名
```

两版都用 NetworkManager，但配置文件位置不同：

-   **服务器版**：/etc/sysconfig/network-scripts/ifcfg-<网卡名>
    
-   **桌面版**： `/etc/NetworkManager/system-connections/` 下按连接名存放
    

改完都要 `nmcli connection reload` ，再 nmcli connection up 连接名 才生效。（用上面 `nmcli modify` 改的，只需最后一步 `up` ；手工动过配置文件的，才需要先 `reload` 。）

**防火墙**：服务器版是 firewalld。

```
systemctlstatusfirewalld
firewall-cmd--list-all
firewall-cmd--add-port=8080/tcp--permanent
firewall-cmd--reload# 加完必须 reload
```

桌面版默认不一定启用 firewalld，先 `systemctl status firewalld` 和 `ufw status` 两条都跑一下，确认本机到底用的哪套，再决定改哪里。

## 五、用户、权限与文件

| 命令  | 说明  |
| --- | --- |
| useradd -m 用户名 | 建用户并带家目录 |
| passwd 用户名 | 改密码 |
| usermod -aG 组名 用户名 | 追加附加组（ `-a` 千万别漏） |
| id 用户名 / groups 用户名 | 查 uid、gid、所属组 |
| chown -R 用户:组 目录 | 递归改属主 |
| chmod 755 文件 | 改权限 |

## 六、磁盘与存储

| 命令  | 说明  |
| --- | --- |
| `lsblk` | 块设备树，比 `fdisk -l` 好读 |
| `df -h` | 容量  |
| `df -i` | inode 使用率，满了一样报 No space left |
| du -sh /路径 | 目录占用 |
| du -h --max-depth=1 /路径 \| sort -h | 找出是哪个子目录吃满了 |
| `blkid` | 看分区 UUID |
| `mount /dev/sdb1 /mnt` / `umount /mnt` | 临时挂载/卸载 |
| `mkfs.xfs /dev/sdb1` | 服务器版常用 |
| `mkfs.ext4 /dev/sdb1` | 桌面版常用 |
| `lsof +L1` | 查已删除但被进程占用的文件 |
| `pvs` / `vgs` / `lvs` | 看 LVM 卷组与逻辑卷，服务器版装系统常见 LVM |
| xfs_growfs /挂载点 | xfs 分区扩容（先扩分区/逻辑卷） |
| `resize2fs /dev/xxx` | ext4 分区扩容 |

> ⚠️ `mkfs` **、** `fdisk` **之前先** `lsblk` **确认设备名**，搞错盘符就是整盘数据没了。
> 
> ⚠️ `/etc/fstab` 写错会导致系统起不来。改之前先 `cp /etc/fstab /etc/fstab.bak` ，改完用 `mount -a` 验证一遍再重启。

## 七、日志与故障排查

| 命令  | 说明  |
| --- | --- |
| `journalctl -xe` | 最近的错误与相关日志 |
| `journalctl -b -p err` | 本次启动以来的 error 级日志 |
| `journalctl --since "10 min ago"` | 按时间切片 |
| `tail -f /var/log/messages` | 系统日志（服务器版） |
| `tail -f /var/log/syslog` | 系统日志（桌面版） |
| `dmesg -T \| tail -50` | 内核日志，带可读时间戳 |
| `last` / `who` | 登录记录、当前在线 |
| `lastb` | 登录失败记录，查暴力破解 |
| `journalctl -k \| tail -50` | 内核日志，等价于 dmesg |

还有几个值得记住的日志位置：

-   `/var/log/secure` （服务器版）/ `/var/log/auth.log` （桌面版）——登录与提权审计
    
-   `/var/log/dnf.log` 或 `/var/log/apt/history.log` ——包管理操作历史
    

## 八、麒麟特有的那些

### 1\. 麒麟的版本与标识

-   `/etc/kylin-release` ：麒麟的版本标识文件， `cat` 一下比什么都直接
    
-   `/etc/.kyinfo` ：系统标识与授权相关信息，排查激活问题时值得看一眼
    
-   `nkvers` ：麒麟专有的版本查询命令，一次输出系统版本、内核、构建信息（若是精简安装、本机没有这条命令，就回到 `/etc/kylin-release` ）
    

### 2\. kysec 安全机制

kysec 是麒麟的安全增强层，作用位置和 SELinux 类似，管三件事： **执行控制** （哪些程序允许运行）、 **文件保护** （关键文件防篡改）、 **网络控制**。

配置与状态在 `/etc/kysec/` 目录下。至于命令行的查询与开关工具， **各版本工具名不完全一致，不要照抄别人的命令**，先在自己机器上确认装了哪些：

```
ls/usr/bin/usr/sbin|grep-ikysec
```

看清有哪些工具，再用 `--help` 确认参数。图形化侧则走「安全中心」。

> ⚠️ **这是麒麟上最容易踩的坑之一**：执行控制开启时，从别的地方拷过来的二进制文件可能直接被拒绝执行。现象是"文件明明有 `x` 权限， `chmod 777` 了还是跑不起来"。这时候别在权限上打转，先查 kysec。

### 3\. 麒麟自带的工具集

软件商店、系统监视器、麒麟助手、网络管理、更新管理这些图形化工具，命令名同样以本机为准。一条命令全捞出来：

```
ls/usr/bin|grep-ikylin
```

要在脚本里调用，一定先用上面的方式确认名字，别凭记忆写。

### 4\. 安全中心与防火墙，不是一回事

图形界面里的「安全中心」管的范围比防火墙宽：除了网络访问，还涉及应用权限、外设（比如 U 盘）管控、账户安全策略这类东西。这些策略落在哪个配置、能不能用命令行改，各版本差异很大，本文不硬写。

但有个排查思路值得记住： `firewall-cmd` **放行的是网络层，不代表应用层策略就放行了。** 遇到"端口明明加了还是连不上"、"U 盘插上认不出来"这类问题，先怀疑图形化的安全策略，再回头查 firewalld。

### 5\. 激活与更新

激活状态优先在系统自带的「激活 / 授权管理」图形工具里看；命令行侧各版本差异较大，不确定就回到图形界面，别硬猜命令。

系统更新建议走自带的更新管理器，它会按麒麟的源规则处理依赖。手工改源、手工升级，在不熟悉这台机器的前提下风险远大于收益。

* * *

记住以下五点：

1.  **改配置前先备份**：cp 文件名 文件名.bak.$(date +%F)，一分钟的事。
    
2.  **源千万不要混搭**：Ubuntu、Debian、CentOS 的源文件和密钥都不能直接搬进麒麟。
    
3.  **桌面版不等于 Ubuntu，服务器版不等于 CentOS**：八成一样，剩下两成就是你加班的原因。
    
4.  **麒麟特有的工具和 kysec，命令名先用 grep 确认**，别信记忆、别信网上抄来的。
    
5.  **生产环境动手前先** `systemctl status` ，别在业务高峰跑全量 `dnf update` 。
