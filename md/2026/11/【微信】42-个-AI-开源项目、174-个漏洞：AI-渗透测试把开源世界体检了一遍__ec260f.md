**数据背后的五条规律**

1\. "默认值"是最高频的坑。CWE-798 硬编码密钥出现 11 次，加上各类默认口令，几乎每个项目都栽在"没设环境变量就带病上线"。khoj 的!secret、poster-design 的xpai-design-admin-secret、coai 的 root/chatnio123456，同一类错误换了三个名字。

2\. SSRF 是 AI 应用的高发区。34 条 SSRF 是全场最大漏洞族。原因很直白：AI 应用大量内置"截图、网页读取、链接预览"能力，全是让服务端浏览器去访问 URL的天然入口；poster-design 的 puppeteer 截图接口甚至没鉴权，file://、云元数据 169.254.169.254 想访问就访问，还能把渲染结果以图片回显给攻击者。

3\. 缺失认证与越权是"孪生兄弟"。CWE-306（缺失认证）15 处 + CWE-639（IDOR）8 处。maxun 的 GET /storage/recordings 直接返回所有用户的 Robot 及其 Google/Airtable OAuth 令牌；AI-Infra-Guard 更离谱——把请求头里的 username 当身份，没有任何凭证校验。

4\. Agent 工具链成了新攻击面。当"LLM 调用工具"成为标配，工具本身就成了 RCE 通道：maxun 的 script、AI-Infra-Guard 的 execute_shell（shell=True 执行 LLM 生成的命令，sandbox_execution 标志是死代码）、open-multi-agent 的 Consequential bash。给 LLM 一把工具，就等于给提示注入一把钥匙。

5\. 中危占 58%，但组合起来就是超危。为什么中危能占到近六成？101 条中危里，SSRF + 路径穿越 + 硬编码密钥任意两两组合，都能串成完整攻击链——单独看都不致命，连起来就是接管。

**给开发者的通用修复清单**

| 漏洞族 | 一句话修复 |
| --- | --- |
| 硬编码密钥/口令 | 删除默认值，缺失即拒绝启动；随机生成 + 定期轮换 |
| SSRF | 协议与 IP 白名单（禁 file://、内网、云元数据）；禁 `--no-sandbox` ；接口加鉴权限流 |
| 文件上传 | 扩展名白名单 + 魔数校验；服务端随机文件名；静态目录与存储分离 |
| 越权/IDOR | 所有按 id 的查询强制 `userId` 归属过滤，统一封装 ownership helper |
| JWT | 白名单签名算法；校验 exp/nbf；密钥 ≥32 字节 |
| 任意文件读取 | 读取前 `realpath` 校验，拒绝解析到项目根之外的路径 |
| Agent 工具 | 默认最小工具集；危险工具人工确认；真正落地沙箱（非登记个标志） |
