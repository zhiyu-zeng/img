## 01先过五道关：本地跑大模型要搞清楚什么

在选模型、装框架之前，先建立一张总图。本地 AI 解题，核心变量就五个：

-   内存/显存：决定本机能跑多大参数的模型。
    
-   带宽：决定速度（token/s），这是最容易被忽视的一项。
    
-   模型：选什么模型，看参数量与量化程度。
    
-   推理框架：用什么把模型跑起来，不同框架速度差异很大。
    
-   提示词与 Agent：是否给 Agent 加提示词、知识库、外部工具。
    

这五项不是并列关系，而是层层递进：硬件定上限，框架定效率，提示词与 Agent 定「解题能力天花板」。下面逐项展开。

## 02模型怎么选：稠密与混合专家，看场景

开源大模型大致分两类。稠密模型（Dense）每个 token 都激活全部参数，更擅长强推理；混合专家模型（MoE）每个 token 只激活一小部分参数，知识更丰富、交互更快。

![图片](https://cdn.jsdelivr.net/gh/zhiyu-zeng/img@main/img/2026/11/88de172e98cc46ee.png)

对 CTF 这类题型，除密码学方向需要强推理外，多数赛题并不需要模型「想很久」，而是需要大量工具交互和信息处理。因此同等体量下，MoE 或交互更快的模型通常更顺手。起步建议从 20B~30B 级别的开源模型入手，兼顾能力与硬件门槛。选模型时不要只盯参数，先看它是否支持视觉、是否带思维链（Thinking）能力——多模态在截图类、附件类题目上很实用。

## 03推理框架怎么选：控制力与易用性的取舍

框架负责加载模型、调度资源、管理显存。消费级设备（游戏本、MacBook）常见选择：

![图片](https://cdn.jsdelivr.net/gh/zhiyu-zeng/img@main/img/2026/11/c70f0152ab01b713.png)

一句话：追求可控性选 llama.cpp，追求省事选 ollama，Mac 用户优先看 MLX 生态。模型权重开源后，社区会转成对应格式（如 llama.cpp 用的 GGUF、MLX 用的 MLX 格式），按需下载即可。注意 LM Studio 这类「傻瓜式」工具很多高级项调不了，真要压性能还是得回到 llama.cpp 或 MLX 命令行。

## 04量化：用精度换显存与速度

官方开源模型常以 BF16（每个参数 16bit）发布。量化就是把参数精度压缩到 8bit、4bit 甚至更低。以 27B 级稠密模型为例，BF16 满精度约需 50G+ 显存，4-bit 量化后通常可压到 15G 上下（经验值，随模型与框架浮动）。

实测中，4-bit 与 8-bit 在解题质量上差距不大，但 4-bit 速度快约一倍。所以本地优先选 4-bit 量化版本，在「够用」的前提下把速度和显存占用压下来。代价是模型能力略有下降，对硬核推理题影响更明显——这也是为什么强推理场景仍建议保留更高精度。另外，开启 MTP 这类「多 token 预测」加速（模型内置则优先用内置），能把吞吐再提升一截，是本地调优里性价比很高的一步。

## 05提示词与 Agent：决定上限的不是模型

这是最关键也最容易被低估的一环。多位参赛者和研究者都提到一个共同做法：不要照搬庞大的现成 Skills，而是写一段简短的环境提示词，明确告知模型——你的工作目录、可用工具（MCP、虚拟机）、以及「三次实验循环，无进展立即停机并输出状态卡」。

状态卡是核心：卡壳点 + 已解决 + 下一步。没有它，模型会无限试错、甚至走向错误方向；有了它，人和机器才能高效分工。

对黑盒题（如 Web），多 Agent 并发去收集信息、再汇总交给新对话重新探索，是人机协同提效的常用打法。理论题则可把题库切片建全文索引（如 SQLite FTS5/BM25 关键词匹配），再交给模型生成带引用的回答——相比向量 RAG，关键词匹配在确定性题库上往往更准。诚实的边界也要说清楚：纯靠大模型，仍会卡在知识盲区（如某些特定密码学构造），这类题需要知识库补充或人工介入。AI 是加速器，不是替身。

每一步都不需要高端显卡起步，关键是先跑通闭环，再逐步加并发、加外部工具、加知识库。不要一上来就追求满配，先用最小组合验证可行性。

## 07工具清单：能直接看的开源项目

下面几个是公开可查、与「AI 解题/安全 Agent」直接相关的项目，按用途归类：

-   VeriaLabs CTF Agent：多模型并行「赛马」架构，曾在 BSidesSF 2026 解出全部 52 题夺冠。
    
-   CAI（Cybersecurity AI）：内置 35+ 专业安全 Agent，攻防双栖框架。
    
-   NYU CTF Bench / D-CIPHER：学术界的 CTF Agent 评测基准与多智能体系统。
    
-   Cybench：含 40 道真实 CTF 题的 AI 安全评测框架（Stanford 等提出）。
    
-   Cairn：轻量 Web 题解题框架，强调工具交互与推理。
    

这些项目风格不同，但共同点是：把「执行环境 + 多模型 + 工具链」封进一个能自我迭代的循环。选型时先想清楚你是要夺旗实战、还是做基准研究，再决定从哪个入手。

## 08关键提醒：三个绕不开的边界

-   不是万能：密码学知识盲区、强推理题、需要真实业务上下文的研判，仍离不开人。
    
-   合规优先：只在你有权限的环境里跑（自有靶机、授权演练、授权测试），别碰未授权目标。
    
-   比赛规则：正规赛事对 AI 辅助有明确规定，参赛前看清反作弊条款，避免成绩作废。
    

技术能放大能力，但放大的是「你已有的判断力」，不是替代它。先把人这一步练扎实，机器才帮得上忙。
