## 一、一个被两家平台写进条款的“忽略”

场景：报告写“扫描器收到 dnslog（带外回连探测：诱导目标解析攻击者控制的域名，确认指令确实被执行）回连，log4j2（Java 生态常用的日志组件）命中，存在远程命令执行（RCE，即攻击者能让服务器执行自己指定的命令）”。平台判定：忽略。

这不是段子。京东 JSRC 和字节 SRC 两份公开规则里，有一句几乎逐字相同的忽略条款：“未提供成功案例，只是说明理论可行……例如只提供 dnslog 的『log4j2 命令执行漏洞』。”

为什么不算数？dnslog 回连只能证明漏洞触点被触发，证明不了利用链走通。落差的根源只有一句话：报告里只有第一级证据，后面全是空的。

## 二、异常、漏洞，和三个不能混的阶段

**异常**：观察到的、与你以为的“正常”不一致的现象。它的成立只需要“你看到了它”。

**漏洞**：安全控制缺失或失效，导致实际行为偏离预期安全行为，并可能对机密性、完整性、可用性（CIA，数据不被未授权读取/篡改、服务不被中断）造成负面影响。漏洞不是“看到的东西”，是需要证据支撑的判断。

在权威体系里，“发现、验证、定级”是三个独立阶段。NIST SP 800-115（美国国家标准与技术研究院的安全评估指南）把技术评估的目的写成三个动词：identify、validate、assess——识别、 **验证**、评估；它对“测试”的定义是“在指定条件下行使评估对象，比较实际与预期行为”。CERT/CC（卡内基梅隆大学的漏洞协调团队）的流程指南里，Validation 是独立阶段，原话是“分析师验证报告以确保准确性，然后才能采取行动”。

三段产出完全不同：发现产出“现象”，验证产出“可复现路径”，定级产出“带证据的等级”。混用的典型后果，就是把第 1 段的产物写成第 3 段的结论：“日志里有 Token（令牌，登录后证明‘你是你’的凭证）”直接写成“高危，可接管账号”。

## 三、异常升格为漏洞的三个条件

**条件一：偏离预期安全行为。** 说“系统有问题”之前，先回答“系统应该是什么样”。OWASP API Security Top 10 把越权（用户访问到权限之外的数据）列为第一名（BOLA，对象级授权失效），判定锚点是“每个用用户 ID 访问数据的函数都应该做授权检查”——该有的检查缺失才是缺陷本体，“返回了别人的数据”只是现象。

**条件二：可控、可复现的触发路径。** 字节规则的忽略/降级条款几乎就是这条的反面清单：无法稳定复现→降级；仅理论可行、无成功案例→忽略。

**条件三：对 CIA 有可论证的负面影响。** 同一种漏洞，影响证据不同，等级完全不同。以字节规则对 SSRF（服务器端请求伪造）的明文为例：

| SSRF 的证据链位置 | 规则定级 |
| --- | --- |
| 通内网，有回显（探测结果能从响应里看到） | 高危  |
| 通内网，无回显 | 中危  |
| 只能打本机/少量同网机器，少量泄露 | 不超过中危 |

同一个“SSRF 现象”，三种证据位置，三档结论。 **结论是证据链的函数：多一级证据，结论才能高一级。**

## 四、定级的四把尺子

漏洞坐实后，等级由四个证据维度决定（以头部平台公开规则与 CVSS v4.0 通用漏洞评分系统为例）：

**可利用性**：CVSS v4.0 的利用成熟度分四档——无公开 PoC（概念验证代码）也无攻击报告（U）、有公开 PoC（P）、已报告攻击或存在利用工具包（A）。CISA KEV（美国官方维护的已知在野利用漏洞目录）门槛更高，要“已在野外被活跃利用”的可靠证据。“有 PoC”和“有攻击”是两种证据等级，别混用。

**影响范围**：字节规则明文——严重评级需要核心系统权限或千万级以上数据量；单台机器 RCE 加少量信息泄露，通常只到高危。

**前置条件**：是否需要交互、特殊账号、特定配置。TSRC（腾讯安全应急响应中心）评分标准把它列进技术维度三要素：用户交互、攻击媒介、前置条件。

**业务权重**：TSRC 与字节都把业务重要程度显式纳入定级。同一问题在不同平台等级不同，不是黑箱——是尺子权重不同。

## 五、写报告时的自查模板

把全文收进一张能直接放进报告里的模板：

**L1 现象** 　需要观察记录；不足时说：“我观察到了 X”

**L2 控制缺陷** 　需要“预期 vs 实际”对照；不足时说：“疑似缺少 X 校验，待确认”

**L3 可利用条件** 　需要可重放的触发步骤；不足时说：“理论上可利用——未验证假设”

**L4 已验证影响** 　需要影响证明（量级）；不足时说：“影响范围尚未验证”

每个等级只有两种合法状态：拿到该级证据，升级结论；拿不到，用低一级的措辞如实说话。

同一个“日志里出现 Token”的发现，两种写法——

不合格：“攻击者可以利用该问题接管所有用户账号。”

合格：“已确认日志包含认证相关字段；字段的用途、有效性、访问控制尚待验证，在此之前不能认定可导致账号接管。”

后者不出彩，但它是唯一经得起审核的写法。纪律就一句话： **结论的强度，不能超过证据的强度。** 这也是权威体系与头部平台罕见一致的地方——NIST 说测试是“比较实际与预期”，CERT/CC 把验证设为独立阶段，CISA 只认在野利用的可靠证据，头部平台把“仅理论可行”写进忽略条款。漏洞判定，本质上是一门关于证据的手艺。
