[HTB: Garfield](https://0xdf.gitlab.io/2026/11/07/htb-garfield.html)

![](https://pub-4caceed5c57c4466b559b0834d2806c9.r2.dev/img/garfield-cover.webp)

Garfield is an assume breach Active Directory box with a read-only domain controller hidden on an internal network behind the main DC. I’ll find I can write the logon script path for other users as well as files in the SYSVOL scripts folder, and use that to get a shell as the next user. That user can reset the password on their admin account, which has control over the RODC’s computer object. I’ll get administrator access on the RODC two ways, by setting myself as its delegated administrator through a writable managedBy attribute, and with resource-based constrained delegation. Then I’ll rewrite the RODC’s password replication policy so the domain Administrator can be cached there, and show multiple ways to get Administrator, including forcing replication and forging an RODC golden ticket from both Windows and Linux.

For each `msDS-RevealedUsers` entry, I can decode the hex data associated with it:

| Bytes | Field |
| --- | --- |
| 0–3 | Attribute ID, e.g. `0x9005A` = `unicodePwd`, `0x9007D` = `supplementalCredentials` |
| 4–7 | Version of that attribute when it was sent |
| 8–15 | Time of the last originating change (seconds since 1601) |
| 16–47 | Replication metadata |

I’ll write a short Python script that reads lines from stdin and processes them if they are revealed users:

```python
import struct
import sys
from datetime import datetime, timedelta

names = {
    0x9005A: "unicodePwd",
    0x9005E: "ntPwdHistory",
    0x90037: "dBCSPwd",
    0x900A0: "lmPwdHistory",
    0x9007D: "supplementalCredentials",
}

for line in sys.stdin:
    if not line.startswith("msDS-RevealedUsers:"):
        continue
    _, _, _, h, dn = line.split(":", 4)
    attrib, version, timeint = struct.unpack("<IIQ", bytes.fromhex(h)[:16])
    time = datetime(1601, 1, 1) + timedelta(seconds=timeint)
    user = dn.split(",")[0].split("=")[1]

    print(f"{user}[{names[attrib]}] {version}: {time}")
```

Membership in RODC Administrators is really a delegation of control over RODC01. A member can rewrite the allow list (`msDS-RevealOnDemandGroup`) and the deny list (`msDS-NeverRevealGroup`), and can set `managedBy`, which names RODC01’s delegated administrator. It grants no rights anywhere else in the domain. Being able to rewrite which accounts the RODC is allowed to cache is the primitive that leads to Administrator.

### Recover Administrator Credential

#### Strategy

There are a few ways I can get the Administrator credential here. One would be just to wait for them to do something that caches the credential on the RODC. This won’t work here because there’s nothing spurring that caching event.

I’ll show three ways:

1.  I can force DC01 to cache the Administrator hash on RODC01, and then read it with `mimikatz.exe`.
2.  I can do an RODC Golden Ticket, where I use the krbtgt_8245 key with `Rubeus.exe` to forge a TGT for the Administrator. Because they are allowed to be cached on RODC01, DC01 will accept it, and I can then use it in a `Rubeus.exe` Key List request to recover the Administrator hash.
3.  Basically the same as 2, but entirely from Linux using `ticketer.py` to get the TGT, and then pass that to `evil-winrm-py` to authenticate to DC01 as Administrator.

A Kerberos Key List request is a feature built for RODCs. #### RODC Golden Ticket from Linux

From Linux, I can use the krbtgt_8245 AES key to sign a TGT as Administrator, but only with a yet-to-be-merged [PR that adds support for the RODC number](https://github.com/fortra/impacket/pull/2169) (interestingly this PR was created two days after Garfield launched):
