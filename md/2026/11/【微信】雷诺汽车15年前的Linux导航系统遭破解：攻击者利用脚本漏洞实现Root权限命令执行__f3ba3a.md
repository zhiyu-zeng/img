## 一、事件概述

安全研究人员 Rasmus Moorats 发现，2014款雷诺（Renault）Latitude 汽车搭载的 TomTom Carminat LIVE 导航系统存在一条能够实现完整 Root 权限控制的攻击链。

该导航系统运行着基于 Linux 2.6.28.10 定制的操作系统。研究人员通过分析导航设备读取 SD 卡脚本的方式，发现其中存在多个安全设计缺陷。

攻击者在获得车辆导航设备的物理访问权限后，可以通过构造恶意 SD 卡，利用脚本解析器中的命令执行功能与日志路径穿越漏洞，最终借助 Linux 内核的 `core_pattern` 机制，以 Root 权限执行任意命令。

值得注意的是，整个攻击过程不需要破解固件签名，也不需要修改只读系统分区。

研究人员最初只是希望修复导航设备的时钟设置问题。由于设备无法正常打开时间设置菜单，才逐步展开了对系统底层的安全分析。

## 二、受影响系统及安全机制

本次研究针对的是 TomTom Carminat LIVE 车载导航设备。

![图片](https://cdn.jsdelivr.net/gh/zhiyu-zeng/img@main/img/2026/11/bddc3c5206efb80a.jpg)

该设备采用定制版 Linux 系统，内核版本为 Linux 2.6.28.10。

系统虽然采用了较老的 Linux 内核，但仍配置了多项安全保护机制：

| 安全机制 | 具体作用 |
| --- | --- |
| 只读文件系统 | 大部分系统分区禁止写入 |
| noexec 挂载选项 | 阻止在指定分区直接执行程序 |
| SD卡 DRM 验证 | 拒绝未经授权的地图卡 |
| 固件数字签名 | 阻止直接刷入未经签名的修改版固件 |

然而，研究人员发现，系统在处理 SD 卡中的脚本时，仍然存在权限控制和路径校验方面的问题。

## 三、漏洞利用链分析

此次攻击并非依赖单一漏洞，而是通过组合多个功能缺陷，最终实现 Root 权限命令执行。

### 1\. 利用 QEMU 模拟分析启动过程

研究人员首先使用 QEMU 构建模拟环境，分析导航系统的启动过程。

通过模拟系统启动，研究人员发现导航设备会读取 SD 卡中的一个脚本文件：

```
master.script
```

该文件用于自动执行导航界面的相关操作。

负责解析该脚本的程序名为 `ttn` ，并且该程序以 Root 权限运行。

这意味着，脚本中的功能如果存在安全缺陷，就可能直接影响整个导航系统。

### 2\. 发现 SHEX 命令执行功能

研究人员发现， `master.script` 支持一个名为 `SHEX` 的命令。

该命令能够启动系统程序，但存在一个限制：只能接受单个命令名称，不能直接传递命令参数。

因此，单独利用 SHEX 并不能直接实现完整的任意命令执行。

### 3\. 利用 LOG 命令实现路径穿越

另一个关键功能是 `LOG` 。

该命令负责将文本写入指定日志文件，但其路径处理存在缺陷，没有正确限制文件写入位置。

攻击者可以利用路径穿越（Path Traversal）技术，通过 `../` 跳出预期日志目录。

由于负责处理脚本的 `ttn` 程序具有 Root 权限，因此日志写入操作也继承了 Root 权限。

这意味着，攻击者可以利用 LOG 功能，以 Root 权限写入原本不应被修改的系统文件。

### 4\. 利用 Linux core_pattern 实现 Root 命令执行

将上述两个缺陷串联起来的关键，是 Linux 内核参数：

```
/proc/sys/kernel/core_pattern
```

该参数用于定义进程发生崩溃时，Linux 内核如何处理 Core Dump。

Linux 内核支持通过管道形式配置 Core Dump 处理程序。当进程发生崩溃时，内核可以调用指定的处理程序。

研究人员利用 LOG 的路径穿越缺陷，将经过构造的管道命令写入 `core_pattern` 。

这样，当后续程序触发崩溃时，内核便会按照预先设置的处理方式执行指定脚本。

### 5\. 利用 SHEX 触发程序崩溃

为了触发上述机制，研究人员利用 SHEX 启动：

```
/bin/dbus-monitor
```

当系统中不存在相应的 D-Bus 总线时，该程序会异常终止，从而触发内核的 Core Dump 处理流程。

最终，内核执行了 SD 卡上的脚本，研究人员成功获得 Root 权限。

![图片](https://cdn.jsdelivr.net/gh/zhiyu-zeng/img@main/img/2026/11/254b670fa9110b62.jpg)

整个攻击链涉及以下关键环节：

| 组件  | 利用作用 |
| --- | --- |
| SHEX | 提供受限的系统程序启动能力 |
| LOG | 利用路径穿越实现越权文件写入 |
| `core_pattern` | 利用内核崩溃处理机制执行指定程序 |
| `ttn` | 以 Root 权限解析外部脚本，使上述操作获得系统级权限 |

## 四、Root权限获取后的验证结果

成功获得 Root 权限后，研究人员进一步验证了对导航系统的控制能力。

首先，测试载荷成功触发导航设备重启，证明攻击链已经能够影响系统底层运行。

随后，研究人员使用 Linux 的 `dd` 工具备份设备内部存储数据，并找到了保存时间设置的文件：

```
/mnt/flash/settings.dat
```

通过修改其中的时区偏移量，研究人员将设备时间从 UTC+3 调整为 UTC+2，成功解决了最初遇到的时钟问题。

这一过程证明，研究人员不仅实现了命令执行，还能够读取和修改导航设备内部存储的数据。

## 五、攻击条件与实际风险

此次研究展示的是具有物理访问条件的本地攻击，并非可以通过互联网直接远程攻击汽车的漏洞。

攻击者需要满足以下条件：

1.  能够接触目标车辆及其导航设备。
    
2.  准备经过特殊构造的 SD 卡。
    
3.  将 SD 卡插入导航设备。
    
4.  对系统弹出的脚本执行提示进行确认，允许执行 `master.script` 。
    

因此，该攻击链并不意味着攻击者可以通过互联网直接控制汽车的发动机、方向盘或制动系统。

不过，在共享汽车、租赁汽车以及车辆维修场景中，攻击者可能获得短暂的设备物理访问机会。

一旦攻击成功，导航系统中的数据就可能面临泄露或篡改风险，潜在影响包括：

-   读取设备内部存储数据。
    
-   获取系统最高权限。
    
-   修改导航设备配置文件。
    
-   访问可能保存的联系人及位置相关数据。
    
-   修改系统文件及运行环境。
    

研究证明的是导航主机 Root 权限获取，并未证明可以进一步控制车辆的转向、制动或动力系统。

## 六、为什么老旧车载Linux系统仍然存在安全隐患？

此次研究反映出一个长期存在的问题：汽车的使用寿命往往远远超过其车载软件的安全维护周期。

与普通计算机不同，汽车中的信息娱乐系统、导航设备和嵌入式控制单元，可能在车辆投入使用多年后，仍然持续运行原有的软件版本。

本次研究涉及的 Linux 2.6.28.10 内核已经相当老旧，而车载导航系统也未必能够像普通 Linux 服务器一样及时获得安全更新。

此外，这次攻击还暴露出几个值得关注的设计问题：

**1\. 高权限脚本解析**

将外部存储介质中的脚本交给 Root 权限程序解析，扩大了恶意输入可能造成的影响。

**2\. 文件路径校验不足**

日志功能没有正确限制文件写入路径，导致普通功能被转化为高权限文件写入入口。

**3\. 安全机制之间存在盲区**

只读文件系统、noexec 和固件签名等保护措施，并不能阻止所有通过内核接口和高权限程序实现的攻击。

**4\. 车载设备缺乏长期安全维护**

汽车可能继续使用十几年，但导航系统的固件和安全组件未必能够获得相应周期的维护。

## 七、安全建议

针对老旧车载导航系统及嵌入式 Linux 设备，建议采取以下措施：

| 建议  | 具体措施 |
| --- | --- |
| 限制外部介质 | 不要插入来源不明的 SD 卡或 USB 设备 |
| 控制脚本执行 | 对外部脚本增加严格的签名验证和权限检查 |
| 检查设备更新 | 向汽车厂商或授权经销商确认是否存在安全更新 |
| 保护车载数据 | 避免在不可信环境中连接个人手机及导入敏感数据 |
| 加固系统权限 | 避免使用 Root 权限执行外部输入脚本 |
| 修复路径穿越 | 对文件写入路径进行规范化处理和目录边界检查 |

对于车载设备开发厂商，建议重点检查脚本解析器、日志处理模块、外部存储介质访问接口，以及 Linux 内核相关配置。

## 八、事件核心技术总结

本次研究最值得关注的不是某个单独的 Linux 漏洞，而是多个看似普通的功能缺陷如何组合成完整的 Root 权限攻击链。

**攻击链流程：**

```yaml
构造恶意 SD 卡
      |
      v
植入 master.script
      |
      v
ttn 以 Root 权限解析脚本
      |
      v
LOG 命令路径穿越
      |
      v
越权写入 /proc/sys/kernel/core_pattern
      |
      v
SHEX 启动 dbus-monitor
      |
      v
触发程序异常终止
      |
      v
Linux 内核执行预设处理程序
      |
      v
成功获取 Root 权限
```

**核心结论：**

-   **攻击对象：Renault Latitude 2014款汽车的 TomTom Carminat LIVE 导航系统。**
-   **系统环境：定制 Linux 2.6.28.10。**
-   **主要问题：高权限脚本解析、路径穿越、内核 Core Dump 处理机制组合利用。**
-   **攻击结果：成功获得 Root 权限，并读取、修改内部存储数据。**
-   **攻击限制：需要物理访问设备，并获得驾驶员对脚本执行提示的确认。**

这项研究再次提醒我们：车载信息娱乐系统和导航设备同样属于需要重点保护的嵌入式计算平台。即使设备已经上市十多年，只要仍在实际使用，其底层软件中潜藏的安全风险就不应被忽视。
