· **ARTEX**：百度首届「Agent+」攻防挑战赛全国总冠军作品，LLM 多 Agent 驱动的自主渗透测试系统，Go 后端 + Next.js 前端，单二进制交付。

· 本篇基于社区备份的最后一版 v0.3.15（2026-10-07）做源码级拆解：93,282 行 Go、planner 共享 todolist、worker 过程级信息交换、allow/deny/ask 三态审批闸门，全部在源码中定位验证。

## 一、它是谁：从比赛冠军到删库跑路

ARTEX 最早进入大众视野是 2026 年 9 月 3 日。首届「Agent+」攻防能力挑战赛在成都落幕，这项由百度安全应急响应中心联合快手、滴滴、度小满等十余家企业 SRC 主办的比赛吸引了全国 150 多支战队，ARTEX 在 8 强总决赛路演中拿下全国总冠军。硬指标很能说明问题：百度靶场实跑 67.83 分（榜单第七，有效耗时 5 小时 8 分，消耗约 4.56 亿 Token），腾讯 TSecBench 盲测 89.78 分（第六，约 2.71 亿 Token）——靶场实跑单项都不是第一，但靠 50% 作品评审 + 50% 靶场实测的双轨加权，综合总分反超夺冠。评审看重的全流程自动化逻辑、误报率、单高危发现时长这些「工程质量项」，正是它后来开源代码里那些工程细节的来处。

比赛结束后作者开源了全部源码（AGPL-3.0），从 7 月底建仓到 10 月初密集演进到 v0.3.15。转折发生在 10 月上旬：原仓库被删除，GitHub 返回 404。但代码没有消失——一周之内社区冒出大量镜像仓，我们检索「ARTEX」同名仓库已达 975 个，热度最高的国际版镜像 2473 星、2486 forks，多个备份仓库都在 README 第一行标注「ARTEX 最后一个版本纯源码备份」。本篇的研究底稿，就是 clone 自其中一个备份仓库，以 git 提交时间与 CHANGELOG 交叉核对过版本真实性。

为什么一个删库的框架值得拆？因为它是国内首个有顶级赛事冠军背书、且完整走完「比赛—开源—爆火—删库—社区自救」全周期的自主渗透系统。它的架构决策不是玩具级的，而是被 150 支战队同场竞技检验过的。看完这篇你会明白：自主渗透这件事，真正的门槛不在「接上大模型」，而在状态管理。

## 二、先看脸：仪表盘长什么样

ARTEX 交付形态是一个 Go 单二进制（前端静态导出后用 go:embed 内嵌），启动后默认监听 8787 端口，浏览器打开就是完整的控制台。整体界面走暗色工作台风，信息密度很高但分区清晰：仪表盘总览页同时呈现任务状态、Token 消耗曲线和实时活动流，一次任务烧掉多少亿 Token，在这里一目了然。

几个值得停留的细节：任务列表里每个任务有独立的生命周期状态；「执行过程」页签能下钻到每一次会话和工具调用；「探索链路」把 agent 的推理路径画成图；「发现」页聚合全部漏洞结论，「资产」页则是跨任务共享的资产真值库。对运维型团队更友好的是流量录制页——所有工具调用经过内置 MITM 代理留痕，事后取证有完整流量包可查。这套 UI 的完成度不像个人项目，更接近一个商业产品的工作台。

## 三、真门槛：双图架构，把「记性」交给数据库

几乎所有 LLM 渗透Agent 的死法都一样：上下文一长就忘事，多步一深就迷路。市面上一大批「AI 渗透工具」的本质是把 nmap 结果丢给大模型让它写报告，跑两步就断链。ARTEX 给出的解法是把 Agent 的全部状态从上下文里搬出来，落进 PostgreSQL 的两张图里——这也是它文档里自称的「双图架构」。

**资产图（Asset Graph）** 是全局共享的资产真值库：根域名、子域、IP、服务、应用、端点六类节点按父子关系组织、归属到公司，跨任务复用同一份数据。关键在于去重和父子关系全部由程序计算，Agent 只提交原始信息——不指望大模型来维护数据一致性，这是全文最重要的一句设计哲学。

**探索图（Exploration Graph）** 则每个任务独立一份，记录这一次渗透的完整思考链：goal（目标）、intent（意图）、fact（事实）、finding（漏洞）、hint（提示）五类节点，用 spawns、derived_from、yields、proves 四种边连成血缘链。它能回答的问题不是「找到了什么漏洞」，而是「这个漏洞是从哪条推理链推出来的、中间依赖了哪些事实」——任何一条结论都能顺着血缘边回溯到源头证据，这直接解决了 AI 渗透最大的信任问题：结论可审计。

两张图靠锚点表相连：每条意图、每个事实、每个漏洞都被锚定到具体资产节点上。于是既能从探索方向看它打了哪些资产，也能从单个资产反查它被哪些意图测过、得出过什么结论。资产覆盖度、覆盖图这些功能，都是锚点关系的直接产出。

值得强调的是「大多数唤醒派 0 条意图」这个细节。planner 被图变更事件唤醒后先读态势，没有新方向就不派活——克制，是自主系统能长时间跑而不跑飞的前提。此外 planner 每次唤醒都是全新会话（无状态），但持有一份按任务保留、跨唤醒共享的 todolist：一条串行利用链（发现注入点→拿凭据→横向→提权）记录一次，之后每轮只对「前置已完成、依赖的 fact 已存在」的下一步派意图。我们在 agent/planner.go 里定位到了这份 todos 存储，按探索 ID 键控、带互斥锁，与文档描述完全一致。

另一条源码可查的机制是 worker 之间的「过程级信息交换」。一个 worker 执行中踩到的报错、隐藏参数这类观察，未必值得写成正式 fact，但对后续 worker 很有价值。ARTEX 给了三个工具：search_all_worker_traces 按关键字检索本任务其他 worker 的执行过程、list_worker_traces 列出有哪些工作跑过、get_worker_trace 取具体步骤的完整内容。信息以「执行过程」为粒度在 worker 之间流动，但边界不变——每个 worker 仍然只做自己领到的那条意图。站在彼此肩膀上，而不是挤成一团。

## 四、安全带：三态审批闸门与全量留痕

自主渗透最让企业睡不着觉的不是「打不进去」，是「打进去之后干了什么控制不住」。ARTEX 在工具调用层加了完整的拦截审批体系，我们在 intercept 包里验证了实现：每一条工具调用在 PreToolUse 阶段过一遍规则引擎，规则从数据库加载、内存缓存、按优先级排序，三种动作——allow 直接放行、deny 直接拦截、ask 挂起等待人工在页面上批准或拒绝，超时行为可运行时配置。

内置规则的设计有真实的血泪教训感。比如 0.3.15 新增的「删除类接口路径」拦截：此前破坏性规则只认 DELETE 方法，但多数业务的删除接口用 GET/POST 就能触发，一条 curl 就能真删数据。新版补了路径规则，同时做了防误拦设计——匹配 delete/del/remove 等动词时要求后面必须跟分隔符，/delivery、/details、/delta 不会被误杀。规则匹配的颗粒度做到了这种程度，说明作者真的在真实环境里被咬过。

留痕体系同样是三层的：所有工具执行经过内置 MITM 代理（8788 端口）做流量级记录；探索图的 activity 表记录每一步操作；evidence 包沉淀证据文件。加上「模型兜底审批」的 Token 消耗单独计量、审批详情可展开查看，整个链路达到了可审计标准。对一个会自主调用破坏性工具的系统来说，这套安全带不是可选项，是能不能进企业门的分水岭。

## 五、源码级验证：这些细节骗不了人

本篇没有搭建运行 ARTEX（需要 PostgreSQL + LLM API Key 的完整环境，且原版仓库已删、官方 Docker 源已失效，第三方镜像的供应链安全需要读者自行评估），所有结论来自对备份源码的逐包阅读。但恰恰是纯阅读，让几个「骗不了人」的细节浮出来。

第一是代码体量与结构：Go 代码 93,282 行，拆成 agent、server、db、intercept、guard、enrich、evidence、llmpool、mcphttp、notify、report、traffic 等十几个职责清晰的包，agent 目录下 50 多个文件几乎每个都带对应 \_test.go。这不是演示项目的心气。

第二是 CHANGELOG 的成色。0.3.15 的更新说明里，漏洞推送功能上线后跟着一整节安全审计自修复：修复通知凭据「改地址保留凭据」的绕过、markdown 渠道对不可信内容零转义导致的链接注入、投递地址的 SSRF（在拨号阶段设防并覆盖 DNS 重绑定）、bot token 经错误信息外泄、汇总消息截断后整批误标成功导致的静默丢失……每一条都是先复现、再修、再补回归测试。能对自己的新功能立刻做一轮这种烈度审计的开源作者，凤毛麟角。

第三是工程细节：升级走「下载新版本→SHA256 校验→冒烟测试→暂存→守护脚本拉起换装→连续 3 次启动失败自动回滚」的完整灰度链；数据库迁移靠每次启动幂等重跑 schema 实现「重启即迁移」；SSE 部署在反代下需要关缓冲这种坑都写进了文档。这些是真实运维过系统的人才写得出的文档。

需要说明的限制：作者在许可证之外附加了「仅限本地学习与隔离环境验证，禁止对任何线上系统发起测试」的使用声明（无论是否授权）；在线 Demo 已随删库失效；社区二方开发活跃（如月落二开版、代码审计增强版、国际多语言版），但恶意篡改风险需自行甄别，建议只读源码、不跑来路不明的二进制。

## 六、同类对比：自主渗透这盘棋下到哪了

把 ARTEX 放回 2026 年自主渗透工具的坐标系里，格局是「一边巨大、一边认真」。一边是 Strix 这类 7 万星量级的通用型选手，走「万能 Agent 顺手做安全」路线，生态大但渗透纵深浅；另一边是认真把渗透当系统工程做的垂直框架——ARTEX、PentAGI、Cybermes、DarkMoon 都在此列（后三者本号往期均已拆解）。

ARTEX 的差异化护城河有三条：其一，双图架构带来的可审计性——结论有血缘链、过程有 activity 留痕，这是「敢给企业看」的前提，同类开源框架里没有第二家做到这个完成度；其二，赛事检验——TSecBench 89.78 分是盲测靶场实跑出来的，不是 README 自封的；其三，纯 Go 单二进制交付，部署体验碾压一众 Python 玩具。短板同样明显：Token 消耗以亿计（比赛一轮 4.56 亿），成本劝退；原版停更后演进不确定性全压在社区身上；且作者明文禁止线上使用，实质是个研究品而非生产力工具。

给不同读者的建议：架构研究者重点读它的双图 schema 和 planner 实现，这是全仓库最值钱的两千行；红队工程化团队可以把 intercept 三态审批和 MITM 留痕抄进自己的平台；普通读者把它当作理解「AI 自主渗透真实水位」的标尺——冠军作品也需要 5 小时、2.7 亿 Token 才能在盲测靶场拿 89 分，那些宣称「一句话全自动拿shell」的项目，先想想它省掉了什么。

## 七、优缺点与适用场景

**优点：** 双图架构带来的可审计性与状态管理是同类最强；事件驱动 + 共享 todolist 让多步攻击链稳定推进不跑飞；三态审批闸门 + MITM 全量留痕，安全带系得扎实；Go 单二进制 + 幂等迁移，部署运维成熟；赛事冠军背书，架构经过同场竞技检验。

**缺点：** Token 成本以亿计，一把火烧穿普通团队预算；原仓库已删、官方镜像源失效，供应链风险转移到使用者身上；作者附加「禁止线上使用」条款，定位研究品；PostgreSQL + LLM Key 的依赖组合对新手不算友好；社区二开版本质量参差。

**适用场景：** 企业攻防团队研究 Agent 工程化架构（重点抄双图与审批设计）；安全团队在隔离靶场验证 AI 自主渗透的真实能力边界；蓝军把它当「AI 攻击面标尺」校准自家检测覆盖；学习者读源码理解多 Agent 系统的状态管理范式。不适用：直接用于生产渗透（作者明文禁止）、预算敏感场景、以及对第三方镜像不加甄别的直接运行。
