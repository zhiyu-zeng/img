漏洞概况

NGINX 是一款开源的高性能 Web 服务器、反向代理服务器，也常被用作负载均衡器和 API 网关，是全球部署量最大的开源 Web 服务器之一。

近日，F5 官方发布通告，修复了 NGINX 的 5 个内存安全漏洞，分别影响 HTTP/2、HTTP/3、DNS 解析及邮件代理等功能的特定配置。其中 CVE-2026-123007 影响启用 HTTP/2 的未修复实例，攻击者无需任何身份认证即可远程执行代码，获得 NGINX 工作进程权限；在满足相关环境条件时，还可串联 Linux SCTP 内核漏洞实现宿主机提权与容器逃逸。

缺陷代码自 1.9.5（2015 年 9 月，HTTP/2 支持首个版本）起存在于每一个官方发行版，潜伏超过十年。攻击者成功利用可在受影响服务器上执行任意代码，亦可导致子进程崩溃、业务中断。建议受影响用户尽快开展自查并修复。

## 漏洞原理

HTTP/2 有一套发送额度账：响应数据进输出队列先扣额度，流被取消时把没用完的额度退回去——相当于仓库发货先冻结库存、退货再解冻。nginx 的退款函数把额度加回连接窗口时 **不检查上限**：攻击者让两条 896 字节的响应卡在队列里再取消它们，窗口被退到 2^31-1+1792，冲破协议天花板。此后每条 WINDOW_UPDATE 的守卫按无符号算"上限减当前值"，负差值回绕成天文数字，任意增量都被放行；窗口被 85.9 亿个合法帧推过 2^63 后变成负数，nginx 把这个负数当成拷贝长度交给 memcpy，堆被读写穿——先泄露 14393 字节内存拿到全部基址绕过 ASLR，再把清理回调改写成 system()。连接收尾时 nginx 亲手执行了攻击者的命令，实测命令以 worker 身份（uid=101）落地。

## 漏洞复现

本文于 11 月 20 日、25 日与 26 日三次独立完成 CVE-2026-123007 全链复现，其中最终轮由 **独立 Kali 攻击机** 发起：全程零凭据，直接打靶标 HTTPS 端口，完整利用后交互 shell 以 worker 身份（uid=101）弹回攻击机，服务未中断。

| 角色  | 配置  |
| --- | --- |
| 靶机  | Docker 29.1.3，4 核，镜像 `nginx:1.31.8` |
| 靶标指纹 | binary sha256 `f617a134…c13662` ，Debian 13.7，glibc `2.41-12+deb13u4` ，OpenSSL 3.5.7 |
| 监听  | 443/TLS1.3 + ALPN h2， `worker_processes 4` ，静态页 896 字节 |
| 攻击端 | 独立 Kali 攻击机（桥接同网段），Python 3.10 + cryptography 49.0.0，gcc 编译 `streamer` 原生辅助 |

左窗：nc 监听收到的交互 shell（uid=101(nginx)）；右窗：利用链全程日志——引导、账目破坏、85.9 亿帧灌流、14393 字节泄露、ASLR 解析、payload 派发（740.76 秒 / 119.02 GiB）。

修复方案

### 官方修复方案

官方已发布修复版本，请升级至 1.31.9（主线）或 1.30.7（稳定分支），升级后必须 restart 而非 reload——reload 不替换正在运行的二进制，老 worker 带着缺陷代码继续跑：

-   https://github.com/nginx/nginx/releases/tag/release-1.31.9
    
-   https://nginx.org/en/security_advisories.html
    

### 临时缓解措施

1、临时禁用 HTTP/2。关闭受影响服务的 HTTP/2 功能，移除监听配置中的 http2 参数，并在支持的版本中设置 `http2 off;`，阻断 CVE-2026-123007 和 CVE-2026-123633 的已知攻击路径。实施前应评估对 gRPC 等依赖 HTTP/2 业务的影响。

2、临时禁用 HTTP/3／QUIC。移除 QUIC 监听配置，设置 `http3 off;`，必要时通过防火墙封禁对应 UDP 端口，降低 CVE-2026-121810 的利用风险。

3、调整动态域名解析及子请求配置。避免使用 SSI、mirror 等子请求配置，避免代理目标域名包含变量，改用指向固定后端 IP 的上游配置。

4、限制邮件代理服务的访问范围。通过防火墙或白名单仅允许可信来源访问邮件代理端口，不需要对外提供服务时关闭监听或绑定回环地址。

### 升级与缓解的注意事项

| 项   | 状态  |
| --- | --- |
| 1.9.5 – 1.30.6 及更老的分支（如 1.28） | 官方不回移补丁，<br><br>必须跨版本升级到 1.30.7 / 1.31.9 |
| ingress-nginx（社区版）捆绑的 1.27.1 | 项目已归档，不会再发补丁，<br><br>需手动关闭 HTTP/2 或<br><br>迁移到 F5 维护的 Ingress Controller |
| NGINX Plus R34 – R36 | 无修复版本，只能迁移到 37.x 固定版 |
| HTTP/2 关闭的缓解范围 | 只覆盖 123007 与 123633；对 123634、<br><br>121810、113425 无效，不能当作万能开关 |

排查时用 `nginx -T` 找暴露面，用 `openssl s_client -alpn h2` 验证端口是否真在说 HTTP/2；被 CDN 覆盖的源站要单独测——源站只讲 HTTP/1.1 时此漏洞不可达。利用过程会在 access log 留下特征：同一连接大量轮换的 `206 GET /index.html` 、持续数十分钟的长连接，结合 `alert ... exited on signal 11/6` 应按已遭遇利用处置。
