蓝牙测试工具

在IOT测试中，蓝牙BLE协议是非常常见的通信协议，为此有非常多的工具可以进行蓝牙抓捕和数据分析，下面介绍小编常用的测试蓝牙的工具：

## 小米手机抓包

1.小米手机（APP+设备）

对于APP+物联网设备的组合，常见的蓝牙抓包就是使用小米手机自带的蓝牙分析功能，在拨号键上输入\*#\*#5959#\*#\*，即可开启蓝牙日志功能，再输入一遍即可关闭，然后就可以把蓝牙日志文件导入wireshark进行日志分析。

2.nRF52840（空口抓包）

对于需要空口抓包的设备，可以使用nRF52840进行空口抓包，详细的环境配置见之前的文章分享：

```javascript
https://mp.weixin.qq.com/s/89QUalIccPEfCMX4FmwfCw
```

3.HarkRF One（无线信号录制）

```ruby
https://greatscottgadgets.com/hackrf/one/
```

## HackRF录制重放场景

在大部分情况下，蓝牙BLE的包都能通过手机蓝牙数据包或者nRF52840进行抓包，但是也有一种情况，那就是设备使用自带的遥控器进行蓝牙信号发送，并且还是厂商私有协议，这种无论是手机或者nRF52840都无法抓到蓝牙数据包，也就无法分析，这个时候就可以使用HarkRF One这款工具，它可以对蓝牙信道上的信号进行录制，从而进行重放攻击。

![图片](https://cdn.jsdelivr.net/gh/zhiyu-zeng/img@main/img/2026/11/302d1b96c24bef1e.png)

简单来说就是我们可以通过HarkRF One这款工具来对设备进行蓝牙信号的录制和保存，再通过HarkRF One对保存的信号进行重放，这样就算我们无法抓到蓝牙的空口数据包，我们也可以对设备进行蓝牙重放测试。（当然这里涉及到一些无线射频的知识，不在本篇的分享访问内）

## HackRF操作命令

具体的操作步骤：

把HarkRF One连接到kali上，使用hackrf的命令即可查看设备信息：

```nginx
hackrf_info 查看版本
```

![图片](https://cdn.jsdelivr.net/gh/zhiyu-zeng/img@main/img/2026/11/2f057dea77967e4a.png)

```javascript
hackrf_transfer，
可以用来收发数据，如果用它来接收会从 usb 流入并保存到一个文件里，如果用来发射数据，文件内容会通过 usb 发往 hackrf 并通过天线发射出去
```

下面录制蓝牙信道37-39的命令：

```apache
# BLE CH37  2402 MHz
hackrf_transfer -r cap2402.cs8  -f 2402000000 -s 8000000 -n 64000000 -l 16 -g 16

# BLE CH38  2426 MHz
hackrf_transfer -r cap2426.cs8  -f 2426000000 -s 8000000 -n 64000000 -l 16 -g 16

# BLE CH39  2480 MHz
hackrf_transfer -r cap2480.cs8  -f 2480000000 -s 8000000 -n 64000000 -l 16 -g 16
```

上面命令的含意是将 HackRF 调谐到 2.402 GHz 频率，以 8 MHz 的采样率开始接收射频信号，并配合 16 dB 的 LNA 增益与 16 dB 的 VGA 增益放大信号，持续采集 8 秒钟（共 6400 万个样点），最终将这些原始 I/O 数据完整写入名为 `cap2402.cs8` 的二进制文件中。

在kali中使用上面命令后，就可以分别对蓝牙的37，38，39信道进行录制，然后使用下面命令进行分析：

```css
inspectrum -r 8000000 cap2440_press.cs8
建议用windows进行查看，在linux上看有点小，比较难看到信号
```

重放命令：

```apache
hackrf_transfer -r cap2402.cs8 -f 2480000000 -s 8000000 -n 64000000 -l 16 -g 16
```
