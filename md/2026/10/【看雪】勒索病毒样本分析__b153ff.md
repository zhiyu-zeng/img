### 2.3 根据内存和文件行为设置观察点

通常来说：解密后的代码需要一个安身之所，通常是一个具有可执行权限的新内存区域\*\* `VirtualAlloc` \*\*  
代码段（`.text` ）通常是 **只读** 的。要往里面写入解密后的代码，必须先获得“写”权限 `VirtualProtect`  
**`ReadProcessMemory` / `WriteProcessMemory`**：这对 API 常用于跨进程操作，要是不是跨进程的就是 `WriteFile`  
`CreateThread` 创建一个新线程来执行解密后的代码  
创建一个新的进程来运行病毒

可将下列接口作为候选观察点：

| 观察点 | 可确认的动作 | 不能直接推出的结论 |
| --- | --- | --- |
| `VirtualAlloc` | 申请／提交内存；需看大小、权限和返回值 | 不一定用于解密，也不一定需要申请新区域 |
| `VirtualProtect` | 修改已提交内存页权限 | `.text` 权限以实际页属性为准；修改权限不等于已经写入代码 |
| `ReadProcessMemory` / `WriteProcessMemory` | 通过进程句柄读写地址空间 | 不能仅凭函数名认定跨进程注入 |
| 普通汇编内存写入 | 当前进程直接修改自己的缓冲区 | 不需要调用 `WriteFile` |
| `WriteFile` | 把缓冲区内容写入句柄所指对象 | 不等于向本进程内存写入 |
| `CreateThread` | 创建线程，需看线程入口 | 不一定执行解密后的代码 |
| `CreateProcessA/W` | 尝试创建进程，需看返回值及新 PID | 不等于解密完成，也不等于已经执行成功 |

### 2.5 WriteFile 参数与 PE 缓冲区

下表仅适用于 **32 位 `WriteFile` API 入口、尚未执行函数序言时** 的栈布局；

| 栈位置 | 参数  | 本次值 | 含义  |
| --- | --- | --- | --- |
| `[esp+4]` | `hFile` | `00000278` | 目标对象句柄；路径需从创建／打开记录关联 |
| `[esp+8]` | `lpBuffer` | `048E0000` | 源数据缓冲区地址 |
| `[esp+C]` | `nNumberOfBytesToWrite` | `00000600` | 写 1536 字节 |
| `[esp+10]` | `lpNumberOfBytesWritten` | `0045E7FD` | 实际写入字节数的存放地址 |
| `[esp+14]` | `lpOverlapped` | `00000000` | 未提供 OVERLAPPED；还应核对句柄是否按异步方式打开 |
