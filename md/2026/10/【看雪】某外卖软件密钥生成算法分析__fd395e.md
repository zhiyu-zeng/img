> 💡 **AI 总结（key-points）**
>
> 某外卖软件从APK内60×60 PNG图片派生AES密钥，并从图片RGB最低位还原出含a9字段的加密配置。
> 
> - **AES识别：** S-box重复四次组成32位表项（如0x63636363），交叉引用定位`sub_12FB04`密钥扩展，支持128/192/256位密钥、10/12/14轮，含RotWord、SubWord、Rcon及0x1EB090轮常量表。
> - **密钥回溯：** `sub_8B0F4`调用AES-CBC，`sub_11F614`读取配置项a9；字符串解混淆规则为`out[i]=in[i]^(5+3*i)`，字节0x64/0x31解出“a9”。
> - **摘要派生：** 包名+“WU@TEN”+证书DER的MD5大写字符串 → SHA-256 → 按`M[i]=((D[i]+B[i])&0xFF)^A[i]`变换，结果转hex缓存为图片查表输入。
> - **图片密钥：** assets中无扩展名60×60 PNG，取像素蓝色通道，`x=(b+1803)%60`、`y=(b+3011)%60`、`key[i]=b&蓝通道&0xFE`，取摘要前16字节生成16字节AES-128密钥。
> - **配置恢复：** 图片RGB最低位隐藏带.PIC头的数据，校验后用上述密钥与固定IV 0102030405060708做AES-128-CBC解密，去填充并zlib解压得到含a9的配置JSON。

## 二、密钥来源

我们直接追踪 `sub_12FB04` 的交叉引用，找到了函数 `sub_8B0F4` 。该函数将传入的密钥交给密钥扩展函数，随后调用 CBC 分组处理函数。沿密钥参数继续回溯，可以找到 `sub_11F614` 。  

![图片描述](https://cdn.jsdelivr.net/gh/zhiyu-zeng/img@main/img/2026/10/e86c67aa822c5b4c.webp)
  
这个函数主要完成配置项名称解混淆、配置读取和结果复制，没有直接生成 AES 密钥。  
首先，函数检查 `byte_265A70` ，通过初始化标志避免重复执行下面的字符串解混淆：

```python
sub_41CE8(&asc_261ED5, &unk_262094, 5, 2);
```

这里 `unk_262094` 是混淆后的数据， `asc_261ED5` 是输出缓冲区，5 是解码初始参数，2 是处理长度，解码规则是：

```python
输出[i] = 输入[i] ^ (5 + 3*i)；
```

这两个输入字节是 64 31，计算得到：

```python
0x64 ^ 0x05 = 0x61 → 'a'
0x31 ^ 0x08 = 0x39 → '9'
```

解码后得到字符串 a9。  
随后，函数将 a9 构造成临时字符串对象 v4，并传给 `loc_8E010` ：

```python
sub_16FE60((int)v4, &asc_261ED5);
loc_8E010(v5, a1, v4, 0);
```

其中，a1 是向下传递的上下文参数，v4 指定要读取的配置项，读取结果通过返回对象 v5 接收。  
最后，函数复制配置字符串，并销毁临时对象：

```python
v2 = strdup(v5[0]);
sub_1700BC(v5);
return v2;
```

至此，可以确认 `sub_11F614` 返回的是内部配置项 a9 的字符串值。结合后续 AES 调用可知，该字符串的前 16 个 ASCII 字节用于 AES-128 密钥扩展。接下来需要继续追踪：这份配置从哪里来，又是如何恢复出来的？  
配置读取入口位于 `loc_8E010` ，它根据内部状态选择不同的读取分支，具体的配置加载和字段查找由下游函数完成。这部分存在较多混淆，下面不再逐段贴出伪代码，而是沿当前 APK 的图片配置路径说明处理过程：程序先从图片资源中提取隐藏数据，派生配置解密密钥，再解密、解压得到配置 JSON，最后读取其中的 a9 字段并返回。

摘要输入由以下三部分拼接而成：

```python

```

-   包名获取：sub_8BD58 调用 sub_4EBC0(v11, a2)，获取结果保存到 a1\[4\]。
-   证书摘要计算：调用 sub_4F480(v11, a2)，结果保存到 a1\[5\]。其下游通过 sub_4E61C → sub_4DEF4 获取证书 DER，最终由 sub_63660 计算 MD5 并转换为大写十六进制字符串。
-   字符串拼接：直接在 sub_8BD58 中完成：


拼接结果随后传入 `sub_63A2C`:  

![图片描述](https://cdn.jsdelivr.net/gh/zhiyu-zeng/img@main/img/2026/10/fb08de016d31c517.webp)
  
`sub_63A2C` 调用 `sub_8B4A0` ，先计算 SHA-256，再对摘要的 32 个字节做加法和异或变换。  
其等价逻辑为：

```python
data = (包名 + "WU@TEN" + 证书MD5大写字符串).encode()
D = SHA256(data)

for i in range(32):
    M[i] = ((D[i] + B[i]) & 0xFF) ^ A[i]
```

其中，D 为 SHA-256 摘要，A、B 为两张内置的 32 字节常量表。变换结果转为十六进制字符串，缓存到 a1\[10\]，作为后续图片查表派生密钥的输入。

得到摘要变换结果后，程序从 APK 的 assets 目录下读取图片。该文件没有图片扩展名，实际是一张 60×60 的 PNG。

解码后，程序取得 RGB 像素数据和图片宽高，将像素作为密钥派生的查找表。

接着，将前面缓存的摘要变换结果从十六进制字符串还原为字节，取前 16 字节。对每个字节 b，计算像素坐标并读取蓝色通道：

```python
x = (b + 1803) % 60
y = (b + 3011) % 60
key[i] = b & 图片像素(x, y).蓝色通道 & 0xFE
```

重复 16 次，得到 16 字节的配置解密密钥。

同一张图片的 RGB 最低位中还隐藏着加密配置。程序提取这些最低位，还原出带.PIC 头部的数据并完成校验，再使用上述密钥和固定 IV 0102030405060708 进行 AES-128-CBC 解密，这里 IV 是 16 个 ASCII 字节。。去除填充、执行 zlib 解压后，得到包含 a9 的配置 JSON。
