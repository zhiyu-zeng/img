![图片](https://cdn.jsdelivr.net/gh/zhiyu-zeng/img@main/img/2026/10/7cdaa5479869061a.png)

简单来说就是要一直点捕捉青蛙这个键来捉青蛙，但是我们多点几次会发现，最后一直青蛙我们一直抓不到，于是想是不是通过其他方法找到最后一直青蛙

![图片](https://cdn.jsdelivr.net/gh/zhiyu-zeng/img@main/img/2026/10/cc297b1b2eec97c0.png)

看一下cookie，发现了这个frog_session，把这个cookie进行base64解码，得到'frogs':\[0,1,2,3,4\]

既然这样，解题思路就很明显了，我们只要伪造一个frogs从0-8的cookie就可以了

但是，再伪造之前，我们要先了解这个cookie是怎么的来的，可以看到这个cookie有三个.来分割，第一个通过base64解码发现是已经找到的frog的种类，第二个是根据时间生成的，第三个是签名，签名要根据密钥来生成。

那我们要怎么伪造cookie呢？我们首先要得到密钥，可以通过flask-unsign这个库来爆破出这个cookie的密钥：

![图片](https://cdn.jsdelivr.net/gh/zhiyu-zeng/img@main/img/2026/10/fece09aab2a3cb45.png)

可以看到破解的密钥是qwe123456

之后，我们就能轻松伪造cookie了

Set-Content -Path ".\\session.json" -Value '{"frogs":\[0,1,2,3,4,5,6,7,8\]}' -Encoding ascii -NoNewline  
python -c "import json, flask_unsign; print(flask_unsign.sign(json.load(open('session.json')), secret='qwe123456'))"

这让我犯了难，到底要怎么办呢？

不妨先想一想服务器删除我们上传文件的逻辑。当我们点击上传的时候，文件会被上传到/private目录底下，之后会检查这个文件查看文件中有没有不改出现的内容，或者检查文件类型。当发现文件类型不符合，或者文件里的内容不符合就会删除。如果我们想到了这里，就能发现其实我们的木马文件是成功上传的，只不过存在的使劲按很短而已。

这时候，我们就可以利用这个漏洞，不断上传木马，同时不断发送请求（发送请求的间隔要比发送木马的间隔段短，保证更多的访问取抢文件存在的那一秒，成功几率更大），我们可以用bp的intruder板块来实现

## 刻俄柏的小说（登录才能看！）

发现很明显是反序列化漏洞，我们可以交互的入口在cookie这里：

elseif (isset($\_COOKIE\['user'\])) {

data=base64decode(\_COOKIE\['user'\]);

  
}

可以看到，这里对输入的cookie没有任何的限制，导致我们可以利用这个上传经过序列化的一些内容来远程控制服务器输出

我们要输入什么内容的序列化后的结果呢？可以看看前面定义的类，发现会存在pop链，这是利用魔法方法在里面进行多次跳转然后获取敏感数据的一种payload，主要考察我们怎么一步一步的跳转。

我们注意到，当一个对象时dignose类型，且满足name===this->key && is_object($this->action）的时候，会返回一个函数，当这个函数被返回之后，又会触发shell_exec("this->keyvalue")。这段代码是出发漏洞的关键，其中shell_exec是在服务器中执行命令。而this->keyvalue是取当前对象对象的key和value属性，结合在一起。当我们先触发了\__get（读取不存在的属性）这个魔术方法，并通过检验，返回一个函数。当对象被当作函数来调用后，会触发\__invoke，进而返回shell_exec。如果shellexec这个函数的内容又是我们可以控制的，我们就能直接访问这个服务器的文件系统了。

接下来，我们要找到哪里能触发get，看到userinfo中的return $this->user->username，如果user没有username这个属性，就会触发get这个魔法方法

按照这个方法，我们在往上找，会找到echo "已经登录啦：$this->username";，如果这里的username属性不是字符，就会触发\__tostring()。

要想触发echo "已经登录啦：$this->username"，前提条件是满足前面的两个if的判断，第一个判断不难满足，第二个判断就相对比较难了if (this−>secreta!==this->secret_b)，一位secretb是我们没法控制的一个完全随机的数。我们要绕过这个判断，就要让secreta的值为secretb的“地址”，这样这个条件就能永远满足了。
