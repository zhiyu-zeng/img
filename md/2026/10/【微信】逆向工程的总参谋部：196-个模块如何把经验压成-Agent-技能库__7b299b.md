逆向工程的"总参谋部"：196 个模块如何把经验压成 Agent 技能库

逆向最浪费时间的，从来不是"不会用 API"，而是"不知道先看什么、证据放哪、下一步切哪条线"。有人把这套经验压成了一个开源技能库，196 个模块、219 个文件，专门喂给 Codex 这类 coding agent。这篇拆它的结构与打法，所有引用均为公开开源项目。

本文介绍公开开源工具 r0crawl_skills，仅作技术架构与工程方法分享；不针对任何具体目标，不提供攻击利用链。

01先聊痛点：逆向卡在"下一步切哪条线"

## 痛点：卡在决策而非工具

新手常以为逆向难在工具——IDA 怎么用、Frida 怎么挂。真到了现场才发现，最耗时的不是操作，是 **决策**：样本该先脱壳还是先翻字符串？sign 算不出来是算法没找对还是环境缺了？证据该落在哪份笔记里？

r0crawl_skills 想解决的，正是这个"路由"问题：把散装经验变成可路由的模块，让 agent 知道"现在该调哪一块"。

02它是什么：给逆向 agent 的"技能库"

一句话定位：一个面向 Codex 类 coding agent 的 **逆向工程技能库**，作者 manyuegong33，已在 GitHub 开源。规模是 **196 个专项模块 / 219 个 Markdown 文件**，覆盖从 Web/JS 到固件、恶意样本、CTF 的逆向全链路。

它补的短板很明确：模型有"知识"，但缺"路由"——你丢给它一个样本，它知道很多招，却不知道先出哪一招。技能库把"出招顺序"也写进了提示词。

\# 机制：路由器 + 模块目录

\# 新手四问先收敛，再路由到专项模块：

\# ① 分析什么 ② 哪个动作最关键

\# ③ 手上已有什么材料 ④ 想要什么结果

四问的本质是"先收敛再动手"——很多人在第一问就跑偏了，拿着工具先扫一圈，结果证据散了一地。

04模块覆盖与自带脚本

## 模块覆盖与配套脚本

1 **Web / JS 逆向**：sign / token / cookie / WASM / JSVMP / VMP / AST 解混淆。

2 **移动与二进制**：Android 脱壳、Frida 追踪、Native 二进制分析。

3 **协议与样本**：协议重建（HAR / PCAP）、恶意样本分诊、固件分析、CTF。

4 **轻量脚本**：init_case.py / hash_artifact.py / parse_har_fields.py / compare_jsonl.py；附 10 个脱敏示例剧本。工程化地把"证据落盘"变成了默认动作。

05可复用的工作流：六步收口

## 六步收口工作流

把"我感觉这里是加密"推进到"我有证据证明输入、变换、输出和复现结果"——这套思路本身就可复用：

|     |     |
| --- | --- |
| 步骤  | 说明  |
| ① 侦察打点 | 先看清战场，样本、接口、参数、输入点一个不落。 |
| ② 攻击面入账 | 每个发现立即入账：攻击面｜类型｜状态｜证据指针｜严重性。 |
| ③ 假设驱动验证 | 立假设→预测→发探针→对照；三方向打不动就换路。 |
| ④ 向上组合 | 让结论成链：从单点特征扩到完整还原路径。 |
| ⑤ 三态收口 | 每条攻击面落进证实 / 排除 / 阻塞之一，绝不"疑似"糊弄。 |
| ⑥ 报告交付 | 原始报文进证据，复现步骤进正文，过程叙事进回收站。 |
